方案 C · 定稿建议保留双胶囊：双激活签名 + 统一规格

骨架、顺序、位置与现状完全一致（含订阅页式右对齐、两颗胶囊一击直达），改动全部发生在控件的规格与状态表达上——零新组件、零迁移成本。

  • 双激活签名（核心改动）：类型胶囊激活 = 实白底黑字，源胶囊激活 = 品牌红底白字（红色就是筛选角标在用的 --accent，不是新颜色）。现状里两个维度用同一种"发亮"，扫一眼分不清谁是谁；现在白 = 内容、红 = 来源，"当前是电影 × TMDB"这个组合状态一眼可读。
  • 规格统一：类型胶囊字号 10px→13px、触控高度恢复 40px；源胶囊 11px 降级；搜索键 36→40。全行统一 40px 触控高度，删掉横向滚动兜底。
  • 主次分层：源胶囊用更透明的底板 + 更小字号，次级感明确，不再像四颗并列 Tab。
  • 筛选键不跳：豆瓣视角下筛选键禁用置灰（不消失），"筛选仅 TMDB 生效"由禁用态自己表达，右栏不再跳动重排。
  • 不变的：控件顺序、右对齐位置、玻璃胶囊语言、一击切源——与现状完全一致。
结论。

在「一切留在顶栏、不跳出现有设计风格」的约束下，方案 C 是完整解：骨架与现状完全一致，可感知的变化全部来自执行层——双激活签名（白 = 内容、红 = 来源）、统一 40px 规格、筛选键禁用代替消失、字号触控恢复正常档。方案 A/B 的芯片化与 D 的页面工具行都因跳出既有骨架出局。如果定稿 C，我可以直接按这五条改动落到 discover-view.tsx。
