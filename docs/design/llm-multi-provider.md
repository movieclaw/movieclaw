# 多供应商接入与对话框模型选择

## 1. 目标

- 供应商不再是单例：官方 OpenAI、一家中转、一台自建 vLLM 可以同时接入；
- 接入一家即可用它目录里的**全部模型**，不再只有「默认模型」一个可用；
- 智能体对话框新增「模型」选择入口，放在思维链选择器左侧；
- 同一模型 id 出现在多家供应商时，用户分得清、路由走得对。

## 2. 分层

| 层 | 现状 | 本次改动 |
|---|---|---|
| `movieclaw_llm.LlmRouter` | 早已支持多实例：`实例名/模型id` 精确路由、裸 id 按目录归属、`default` 走默认实例 | 裸 id 命中多个实例时记一条中文日志 |
| `llm_provider` 表 | 单例（全表至多一行） | 多行；加 `name`（唯一，路由键）与 `is_default` |
| `/llm/*` 接口 | `GET/PUT/DELETE /llm/provider` | `/llm/providers` 列表 + 按 id 增删改 / verify / default；新增 `GET /llm/models` |
| 设置页 | 一张状态卡片 | 实例列表，每张卡片可编辑 / 重测 / 设为默认 / 删除 |
| 对话框 | 只有思维链选择器 | 「＋ · 模型 · 思考」三个安静菜单 |

默认实例的不变量与下载器相同：只要还有实例就有且仅有一个默认；第一个
接入的自动成为默认，删除默认时让给剩下最早添加的。IM 通道、字幕翻译、
CLI 不带 `--model` 这些没有选择器的场景都走「默认实例 + 它的默认模型」。

## 3. 模型清单的口径（`GET /llm/models`）

- 一个实例的可选模型 = 预设目录 ∪ 用户补录（`extra_models`，按 id 覆盖
  预设），与 `LlmRouter._catalog` 同口径，清单里出现的模型路由一定能解析；
- 端点上报的 `available_models` 不进清单：它们没有上下文窗口 / 思考能力
  元数据，选了之后自动压缩与思维链菜单都会失效。它继续作为设置页补录
  模型时的提示；
- 每个选项带 `thinking_levels`，思维链菜单随所选模型变化，前端不理解方言。

## 4. 重复模型 id 的处理策略

同一个 id 在两家那里往往不是同一个东西（官方版与中转版的价格、限速、
配额、是否支持思考都可能不一样），所以**不去重**，让用户选走哪家：

| 情况 | 提交给 `session.start` 的 `model` | 对话框展示 |
|---|---|---|
| id 只在一个实例里有 | 裸 id，如 `qwen3.7-max` | `qwen3.7-max` |
| id 在多个实例里都有 | `实例名/模型id`，如 `中转/qwen3.7-max` | `qwen3.7-max（中转）` |

由服务端拍平（`services/llm_config.build_model_options`），前端照单渲染，
不做去重判断。裸 id 只保留给 API / CLI 直接调用的兼容场景：默认实例优先，
其余按添加顺序，多实例同时命中时打日志说明走了哪家。

实例名要求全局唯一、不含斜杠（它是路由引用的前半段）；两个 OpenAI 兼容
端点也能同时接入。

## 5. 选择的存放与沿用

与思维链档位同款三态（`docs/design/agent-thinking-level.md` §4.3）：

- `model` 显式引用 → 用它；`default` → 显式清回默认；留空 → 沿用会话
  最近一条 user 消息的引用（新会话即默认）；
- 生效值写进转录 **user 行**的 `model` 信封字段（零迁移）。不能用 assistant
  行反推：供应商回报的 id 可能带日期后缀、也丢了实例归属；
- 手动压缩沿用同一引用；retry 不传即沿用被重试消息的引用；
- 前端：新任务页从「默认」起；会话页展示值回落到最近一轮的引用，用户没动
  过选择器就不传。换模型后思维链档位清回默认（旧档位可能不在新菜单里）。

## 6. 向前兼容

- 迁移只加列：存量的那一行实例名取预设显示名并设为默认。字幕任务里存的
  `实例名/模型id`（以前实例名就是显示名）迁移后仍能解析；
- 旧版本回退后 `select … limit 1` 仍能读到一行，多出的列被忽略。
