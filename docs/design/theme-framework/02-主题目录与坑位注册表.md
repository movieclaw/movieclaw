# 02 · 主题目录与坑位注册表

## 1. 目录契约

```
apps/web/themes/
├── types.ts                 # ThemeDefinition / ThemeSlots / ThemeCapabilities 类型
├── registry.ts              # 坑位注册表：BASE_SLOTS + DEFINITIONS + getResolvedTheme()
└── netflix/                 # 一个主题 = 一个目录，可整体搬运
    ├── theme.ts             # 唯一入口：export default netflixTheme satisfies ThemeDefinition
    ├── tokens.css           # html[data-theme="netflix"] 变量覆盖组 + 钩子类覆盖（自 globals.css 迁入）
    ├── chrome/              # 结构坑位组件
    │   ├── top-nav.tsx        （原 components/netflix/top-nav.tsx）
    │   ├── tab-bar.tsx        （原 tab-bar.tsx，含 NetflixSettingsNav）
    │   ├── settings-sidebar.tsx
    │   ├── back-button.tsx    （NetflixBackButton + NetflixPageActions）
    │   └── brand-loader.tsx   （Netflix 版加载态包装，若与 MovieclawMark 拆分后仍有主题差异）
    ├── components/          # 主题专属内容组件（允许自取数）
    │   └── library-hero.tsx   （NetflixBillboard）
    └── pages/               # 主题专属整页
        ├── my.tsx              （NetflixMyPage）
        ├── settings-index.tsx  （NetflixSettingsIndex）
        └── subscriptions.tsx   （NetflixSubscriptionsPage）
```

硬规则（解离的全部纪律，共四条）：

1. **主题目录可以 import**：`@/lib/*`（含 api）、`@/components/icons`、`@/components/*`
   基础公共件（modal / poster-image 等）。
2. **主题目录绝不被 import**：唯一例外是 `themes/registry.ts`（静态注册）与
   `app/(app)/` 路由壳 ⚑5。业务组件、基础组件一律不得 `import "@/themes/<id>/*"`。
3. **基础组件绝不 import 主题**：反方向的依赖同样禁止——这自动消灭 vendor 写主题名、
   页面写 `=== "netflix"` 两类越界（grep 可机检，见 04 文档）。
4. **tokens.css 只放 `html[data-theme="<id>"]` 作用域的覆盖**，不写基础样式、不写其他
   主题的钩子。银玻璃没有 tokens.css（:root 即基础 ⚑1）。

## 2. ThemeDefinition 类型契约

```ts
// apps/web/themes/types.ts（示意，签名级）
export interface ThemeCapabilities {
  /** 是否启用液态玻璃（WebGL 画布）。纯色平铺主题 = false */
  glass: boolean;
}

/** 结构坑位：主题可替换的组件位。全部可选，缺省回落基础实现 */
export interface ThemeSlots {
  desktopTopNav?: ComponentType<DesktopTopNavProps>;
  mobileTabBar?: ComponentType;              // 银玻璃无此坑位（undefined = 不渲染）
  settingsSidebar?: ComponentType<SettingsSidebarProps>;
  detailBackButton?: ComponentType<BackButtonProps>;   // { onBack, onPhoto? }
  pageActions?: ComponentType<{ children }>;           // 页面右上悬浮操作簇容器
  libraryHero?: ComponentType<LibraryHeroProps>;
}

/** 主题专属整页（路由壳在 app/(app)/，App Router 无法动态注册路由 ⚑5） */
export interface ThemePages {
  my?: ComponentType;             // 现状：非 Netflix 访问 /my 会 redirect("/")
  settingsIndex?: ComponentType;  // Netflix 移动端设置分区索引页
  subscriptions?: ComponentType;
}

export interface ThemeDefinition {
  meta: ThemeMeta;               // 自 lib/themes.ts，新增 themeColor: string
  capabilities: ThemeCapabilities;
  slots: ThemeSlots;
  pages: ThemePages;
}
```

坑位清单的来源：不是发明的，是**现状 13 处主题分支点的逐一收编**（见 §4 迁移映射）。
新增坑位的流程：先在消费点留 `getResolvedTheme().slots.xxx ?? 基础实现`，再在 `types.ts`
补类型——类型表就是坑位总账。

## 3. 消费方式（外壳与页面怎么写）

```tsx
// app-shell.tsx（改造后示意）
const { slots } = getResolvedTheme(theme.id);
// 桌面顶栏：Netflix 提供，银玻璃走内建侧栏布局（坑位 undefined = 现状分支）
{slots.desktopTopNav
  ? <slots.desktopTopNav … />
  : <内建侧栏布局/>}

// 详情页返回键（media-detail-view 等五处，现状 isNfDesktop 三元）
const BackButton = slots.detailBackButton;   // 解析后已有基础缺省，不 undefined
<BackButton onBack={back} onPhoto={…} />
```

- 消费方**只认坑位语义，不认主题名**：判断"是否结构级主题"改为
  `slots.desktopTopNav != null`（或沿用 `meta.structural`，二者由注册表保证一致）。
- 现状注释里"两处判定必须同源"的约定（isHomeRoute / PageNav 短路）不受影响：
  它们消费的仍是同一份主题事实，只是主题事实的来源从散落布尔变成注册表。

## 5. 钩子类纪律（成文，从注释升为规范）

现状约定散在各文件注释里，此处立为全站纪律（同步补进 web-themes.md §3）：

1. **基座组件挂语义钩子类**（`solid-card` / `solid-popover` / `page-nav-btn` /
   `modal-scrim` / `tooltip-bubble` / `person-hero`…），主题在 tokens.css 里接管外观；
   银玻璃下钩子无基样式 = 零变化。
2. **内联切换控件永不挂浮层钩子**（solid-popover 只给真浮层）——2026-09-20 用户拍板，
   切换胶囊全站一套材质。
3. **圆形按钮除外**（§2.3）：钩子压圆角、不压形状。
4. 新增钩子类 = 新增一条主题可定制面，必须同步登记到 web-themes.md 的钩子清单，
   不允许"只在 tokens.css 里偷偷加选择器"。
