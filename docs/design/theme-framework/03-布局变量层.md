# 03 · 布局变量层

## 1. 为什么布局也要进主题框架

颜色/材质早就是变量了（token 层），布局留白却以三元表达式散在页面里——这是 30 个文件
产生"主题分支感"的主因。目标状态：

```
页面代码：  <div className="page-inset">            ← 不出现任何主题判断
变量定义：  :root            { --page-inset: 1.5rem }      ← 银玻璃 = px-6
            html[data-theme="netflix"] { --page-inset: 4vw }   ← Netflix
响应式：    @media (max-width:767px) { :root { --page-inset: 1rem } }  ← 银玻璃移动 px-4
```

新主题适配布局 = 在自己的 tokens.css 里设变量；新增页面 = 挂语义工具类，
两端同时正确。**纯 CSS，零 JS**（用户拍板 #2）：断点在 CSS 里处理，不引入
useMediaQuery 类的监听与 hydration 时序问题。

## 2. 变量集（起步两档，够覆盖现状全部 44 处三元）

| 变量 | 语义 | 银玻璃（基础） | Netflix | 对应现状写法 |
| --- | --- | --- | --- | --- |
| `--page-inset` | 页面级左右留白（页头/列表/结果区） | 1.5rem；≤767px 1rem | 4vw | `px-6 max-md:px-4` ↔ `px-[4vw]` |
| `--content-inset` | 详情页正文左右留白（标题/简介/分区） | 3rem；≤767px 1rem | 4vw | `px-12 max-md:px-4` ↔ `px-[4vw]` |

- 只有两档断点，与现状完全对齐，不发明新档位。
- Netflix 的移动端也是 4vw（现状如此），靠"netflix 组不写 media query 覆盖"自然表达，
  不需要 per-theme 断点矩阵。
- 详情页档为什么单独一个变量：银玻璃详情正文是 px-12，与页面级 px-6 不同档；
  Netflix 两档同值（都 4vw）——这正是"主题各自表达设计"而非"全局统一"的例子。

## 3. 语义工具类（定义在 globals.css 工具层）

```css
@layer utilities {
  .page-inset      { padding-inline: var(--page-inset); }
  .page-inset-mx   { margin-inline: var(--page-inset); }              /* 横幅/空态卡的外边距形态 */
  .page-inset-bleed{ margin-inline: calc(var(--page-inset) * -1); }   /* 吸顶蒙版满宽的反向抵消 */
  .content-inset   { padding-inline: var(--content-inset); }
}
```

- 命名对齐现有 `insetClassName` 参数的语义（media-row / up-next-row 已有该参数），
  组件 API 不变，只是调用方传的值从三元换成类名。
- `page-inset-bleed` 收编 PageNav 的"调用方负边距必须与留白成对传"的人工约定
  （page-nav.tsx 注释里的坑）——留白改变量后，负边距天然同源，不再可能错位。

## 4. 替换规则（44 处三元 → 类名，逐形态对照）

| 现状写法（银玻璃 ↔ Netflix） | 替换为 | 典型位置 |
| --- | --- | --- |
| `px-6 max-md:px-4` ↔ `px-[4vw]` | `page-inset` | favorites / library-* / search-results 页头、collection-grid、library-collections 等 |
| `mx-6 max-md:mx-4` ↔ `mx-[4vw]` | `page-inset-mx` | 空态卡（content-empty-state、library-filter-bar）、失败横幅、选种横幅 |
| `px-12 max-md:px-4` ↔ `px-[4vw]` | `content-inset` | media-detail / library-item-detail / person-detail 正文 |
| `${insetMx}` 负边距配对（PageNav 蒙版） | `page-inset-bleed` | page-nav.tsx + collection-grid-view 的 insetMx |
| `insetClassName` 缺省值 `"px-6 max-md:px-4"` | 缺省改 `"page-inset"` | media-row / up-next-row |

实施即机械替换：删除 `const isNf = …` / `const inset = …` 声明，className 换语义类。
替换后 18 个文件里 `useTheme` import 若再无消费者则随之删除。

## 5. 边界情形（不是纯留白，明确处置）

| 情形 | 现状 | 处置 |
| --- | --- | --- |
| 设置面板锚定（settings-view）：Netflix 左锚定 pl-12、银玻璃居中窄栏 | 双形态切换 | **留页面级分支，暂不变量化**。它是"居中 vs 左锚定"的结构二态，不是同一档位的取值；若第三个主题也要分叉，再升 `--content-align` 变量或走坑位 |
| activity-view 容器：Netflix 全幅 4vw、银玻璃居中 1180px 栏 | `max-w-[1180px]` 有无 | 同上，留分支；只把其中的 4vw/px-6 换 `page-inset`，`max-w` 差异保留 |
| discover Hero 全出血文字区、`max-w-[1500px]` 栏宽差 | fullBleed prop | 已是组件参数化（HeroSlide fullBleed），保持；数值不进全局变量（各页栏宽不同，不适合全局档） |
| person-hero / sub-hero-card 的"让位推下"（globals.css 桌面档） | Netflix 专属 CSS | 已是钩子类 + tokens.css 作用域规则，随覆盖组整体迁入主题目录，不动 |

原则：**变量层只收"同一语义槽位取不同值"的分歧**；"结构形态不同"的分歧留给坑位或
页面参数。把结构二态硬塞进变量会发明出 `--content-align: center|start` 这类只有两个
主题、各用一次的伪 token，违背简洁优先。

## 6. 验证

- 替换前后双主题截图逐页对比（银玻璃逐像素零变化是硬门 ⚑7；Netflix 允许亚像素级
  反锯齿差异，版式必须一致）。
- grep 门禁：`themes/` 与 globals.css 基础组之外，全站不得再出现 `px-[4vw]` /
  `mx-[4vw]` 字面量（04 文档纳入 CI 可机检项）。
