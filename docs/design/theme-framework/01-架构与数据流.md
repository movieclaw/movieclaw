# 01 · 架构与数据流

## 1. 全景：三层机制的"长完"形态

既有框架（web-themes.md §3.3）的三层不变，本设计把每层"长完"：

```
┌─────────────────────────────────────────────────────────────────┐
│ 主题注册表 lib/themes.ts + apps/web/themes/                       │
│                                                                 │
│   meta 层     ThemeMeta { id, label, …, themeColor ⚑2 }          │
│   变量层     :root（基础） + themes/<id>/tokens.css（覆盖，@import）│
│   结构层     坑位注册表 registry.ts：id → 坑位 → 组件（全表）        │
│   能力层     capabilities { glass } → vendor 收 prop 不问主题名    │
└─────────────────────────────────────────────────────────────────┘
          │ data-theme 属性                │ getResolvedTheme(id)
          ▼                               ▼
   globals.css 变量覆盖组           外壳 / 页面消费坑位组件
   （纯 CSS，零 JS）                （基础实现兜底，永不 undefined 崩）
```

与现状的本质差别：**主题知识只剩一个出口**。此前 30 个文件各自判断 `theme.id === "netflix"`；
此后只有两处合法存在——注册表（主题目录内部）与 `themes/registry.ts`（解析）。

## 2. 主题生效数据流（含首帧）

```
SSR 首帧
  layout.tsx 服务端渲染：
    RESTORE_THEME_SCRIPT ⚑2 —— 由注册表序列化生成（非硬编码白名单）：
      var THEME_COLORS = {"netflix":"#000000", …}   ← THEMES 遍历产出
    localStorage 命中合法主题 id → 写 <html data-theme> + theme-color meta
    （未命中 / 垃圾值 → 不写属性 = 默认主题，行为与现状一致）

hydration
  lib/ui-prefs.tsx：
    初始值取 localStorage 缓存 → 后端偏好接口落定 → 写 data-theme 属性
    （默认主题移除属性；theme-color 观察器照旧）

组件渲染（新增的解析步骤）
  任意组件：const theme = getResolvedTheme(useTheme().id)
    ├─ meta        直接透传
    ├─ capabilities 主题声明 + 基础缺省归并
    └─ chrome/pages  id→坑位→组件 全表查询
                      坑位缺失 → 回落基础实现（无基础实现的坑位 → undefined，
                      消费方按"没有就不渲染"处理，与现状语义一致）

样式
  globals.css @import themes/<id>/tokens.css ⚑3
    html[data-theme="<id>"] 作用域覆盖变量 + 钩子类（solid-* / page-nav-btn 等）
```

防闪烁脚本从"白名单常量"改为"注册表序列化"，是新增主题不漏改的关键：
脚本逻辑不变（仍是那段内联 try/catch），只是白名单与色值表在服务端渲染时由
`THEMES` 数组生成。内联脚本无法运行时查 TS 注册表，服务端拼串是构建期的最近 equivalent。

## 3. 坑位解析语义（完整注册表的核心规则）

```ts
// apps/web/themes/registry.ts（示意）
const BASE_SLOTS: Partial<ThemeSlots> = {
  detailBackButton: PageNavBackButton,   // 基础实现 = 银玻璃现状
  pageActions: StickyPageActions,
  // …有基础实现的坑位才登记；无基础实现的（如 mobileTabBar）不登记
};

const DEFINITIONS: Record<ThemeId, ThemeDefinition> = { netflix: netflixTheme };

export function getResolvedTheme(id: string): ResolvedTheme {
  const def = DEFINITIONS[normalizeThemeId(id)];   // 未知主题 → 默认主题（既有兜底）
  return {
    meta: def.meta,
    capabilities: { glass: true, …def.capabilities },
    slots: { …BASE_SLOTS, …pickDefined(def.slots) },
  };
}
```

四条规则，各对应一条失败路径：

| 场景 | 行为 | 安全网性质 |
| --- | --- | --- |
| 坑位未实现（新主题没画顶栏） | 回落 `BASE_SLOTS` 基础实现 | 新主题可增量开发，永不白屏 |
| 坑位注册了未知名字（拼写错） | dev 构建断言报错，prod 忽略该坑位 | 错误在开发期暴露，不带进生产 |
| 主题 id 不存在（缓存被改坏/下载失败） | `normalizeThemeId` 回落默认主题 | 既有兜底，不变 |
| 主题组件渲染抛错 | 不做 ErrorBoundary 特判（与业务组件同待遇） | 主题是可信同源代码，不加沙箱复杂度 ⚑8 |

## 4. 能力层与 vendor 反转

```
主题定义                          调用点（app 层包装）              vendor
capabilities.glass ──消费──▶  glassEnabled={…}  ──prop──▶  LiquidGlassButton
（netflix: false）                                             （不再 import useTheme ⚑4）
```

- vendor 只认 prop，默认 `true`（不传 = 现状行为，银玻璃零变化）。
- "哪些主题允许玻璃"是主题的设计决策，因此声明放主题定义处，不散在调用点。
- 与现状等价性：现状 = netflix 下不建 WebGL 渲染器；改造后 = netflix 调用点传
  `glassEnabled={false}`，渲染器同样不创建，按下动画交接语义不变。

## 5. 与既有资产的关系（复用什么、动什么）

| 既有资产 | 处置 |
| --- | --- |
| `lib/themes.ts` 注册表 | 保留并升格：`ThemeMeta` 增 `themeColor`；`structural` 布尔标记保留（兼容设置卡与文档口径），结构分支的实际解析改走坑位注册表 |
| `lib/ui-prefs.tsx` 生效链路 | 不动（localStorage → 后端偏好 → data-theme 属性） |
| `lib/page-chrome.tsx` isHomeRoute | 签名不变；内部 `isNetflix` 参数由"主题布尔"改传"是否声明了 desktopTopNav 坑位"？——**不改**，保持显式布尔（全出血让位是 Netflix 设计事实，不是可插拔语义），避免过度抽象 |
| globals.css 2894 行 | 基础组（:root / 公共类）不动；`html[data-theme="netflix"]` 覆盖组（约 415 行）迁往 `themes/netflix/tokens.css`，选择器与值逐行原样搬运 |
| 钩子类契约（solid-* 等） | 不变，文档化为纪律（02 文档 §5） |
| 银玻璃全部组件 | 不动（它们就是"基础实现"本身） |

## 6. 下载预留的缝（本期只留缝，不实现）

- **产物形态**：一个主题 = `themes/<id>/` 目录整体（theme.ts + tokens.css + chrome/pages）。
  将来"下载"= 把目录产物放进约定位置 + 注册表对"运行时出现的主题"走动态 `import()` 分支。
- **注册表的两段式**：本期 `DEFINITIONS` 是静态 import 的字面量；预留第二段
  `dynamicDefinitions`（异步解析 + 加载中回落默认主题），本期不写实现、只保证静态段的
  API 形状与动态段一致（`getResolvedTheme` 同步签名的兜底路径已覆盖"下载的主题还没就绪"）。
- **边界声明** ⚑8：主题代码 = 同源 JS bundle，安装即执行可信代码。市场化的签名 /
  沙箱 / 权限模型是独立立项，不在本框架的承诺范围内。
