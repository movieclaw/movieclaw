媒体库首页：像透视一样自定义

首页现在是一份写死的清单：接下来继续、我的收藏、我的媒体库、每个库一行「最近添加」。它对第一天的用户是对的，对第一百天的用户就开始碍事——六个库六行「最近添加」，而他想看的是「评分最高、我还没看的动漫」。OmniFocus 的透视解决的正是这件事：视图由用户定义，侧栏由用户排列。首页也该如此。

首页原子 行 = 来源 × 排序 × 名字 新增数据表 0 张 新条件语言 0 套 样稿里的排序与命名推荐 真跑
论点

透视 = 规则 + 呈现 + 位置

OmniFocus 一个透视由三部分组成：规则决定筛哪些任务，呈现决定怎么排、叫什么，位置决定它在侧栏第几个、要不要显示。搬到首页上，三部分各有归宿——其中两部分项目里已经有了，只缺最后一部分。

来源

规则 · 已有

一行滚的是哪一批作品：一个库，或一个合集。想要「8 分以上的日漫」，先筛、存成合集、再上首页。首页不新造第二套条件语言。

呈现

排序 · 名字

同一个库，按入库 / 上映 / 最近观看 / 评分 / 随机排，就是五行不同的东西。名字由用户定，系统按排序给推荐：「最近上映的电影」「评分最高的动漫」。

位置

顺序 · 显隐 · 本期要做的

每个成员一份有序的行清单。能藏、能挪、能加、能恢复默认。数据形状照抄侧栏导航的 NavUiPrefs：存的是提示，不是契约。

{ id:"row:8f2c", library_id:3, sort:"rating", unwatched:true, name:"评分最高的动漫" } 一行就是这么一条记录 · 内置行只有 id 和排序 · 合集行把 library_id 换成 collection_id · 名字留空即跟随系统推荐

自定义首页

独立页面 /library/customize · 「＋ 添加一行」在列表底部

member.ui_prefs → home.rows

{
  "home": { "rows": [
    { "id": "up-next" },                       // 内置：排序固定
    { "id": "favorites", "sort": "unwatched_first" },
    { "id": "libraries" },
    { "id": "lib:1", "sort": "release_date" },   // 每库一条默认行，改了排序、名字留空
    { "id": "row:8f2c", "library_id": 3,
      "sort": "rating", "unwatched": true,
      "name": "评分最高的动漫" },                // 用户自己加的；sort 直接是 WallSort 取值
    { "id": "lib:2" },
    { "id": "row:a91e", "collection_id": 7,
      "sort": "release_date_asc" },             // 合集行，名字跟合集走，排序与库行同一组
    { "id": "lib:3", "hidden": true }
  ] }
}
  1. 存的是提示，不是契约。读取时按「存过的按存的顺序，没存过的内置行与每个库的默认行追加在后」合并。新库、新版本加的内置行，老用户一定看得到。
  2. 认不出的 id 直接忽略。库被删、合集被删或被别人改成私有，那一行静默消失。不需要迁移，不需要清孤儿。
  3. 隐藏保留位置。再打开时它回到原来那个位置，而不是队尾。
  4. 名字留空 = 跟随推荐。推荐由排序与来源实时生成；用户一旦手输，就不再跟着排序变。
  5. 没有 asc 字段。方向合并进排序取值：「最早上映」就是现有的 release_date_asc，与系列合集用的同一档。
  6. 隐藏的行不发请求。藏掉三个库的「最近添加」，首页少三次请求。

「只显示我没看过的」开着时推荐名不变，自定义页里这一行的小字多一个「只看没看过的」；首页上什么都不显示。随机的种子按天固定：轮询刷新不换一批，明天再换。
