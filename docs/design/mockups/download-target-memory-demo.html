四个毛病与它们各自的修法。左列是现在的实现，右列是本方案。

现在

apps/web/components/download-target-dialog.tsx

1
复选框默认不勾初值 = 「已有记忆」，第一次必然不勾 → 绝大多数人永远建立不了记忆
2
桶键 = media_type ?? "other"模型推断值，会 null、会随模型版本漂移；动漫/纪录片/综艺全压进三个桶
3
命中即静默提交点下载种子已进下载器，只能靠 toast 的「更改」事后补救
4
预检失败静默回落返回 null 直接弹窗，用户不知道为什么点了下载又弹窗
5
存 localStorage换浏览器/无痕/清缓存即丢；用户看不见也删不掉

本方案

docs/design/download-target-memory.md

1
删掉复选框，自动记忆每次提交后写入（目标未变则不写）；系统观察，不要用户预判
2
桶键 = TorrentCategory搜索标签栏本身的维度，站点 YAML 声明式映射，8 个桶，不参与推断
3
确认条提交前看得见分类、路径、下载器；一次点击确认，一次点击改
4
失效必有原因展开弹窗并说明是预检未收敛、目录没了还是下载器不可用
5
成员级专表 + 就地清除跟人走、跨设备；确认条上一键「不再记住」，不进设置页；不动 app_setting（那个改动回退不安全）
