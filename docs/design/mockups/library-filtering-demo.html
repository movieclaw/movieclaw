媒体库筛选与合集

库过千部之后，海报墙是一条只能从头翻的走廊。可筛的事实其实早就齐了——类型 ID、地区码、评分、片长、分级、画质、观看状态、人物，一个维度都不用重新刮。缺的只是收窄、计数，和把收窄固化下来的能力。

样本库 34 部 · 筛选与计数是真跑的逻辑 新增筛选维度 0 次刮削 服务端改动点 1 处候选集 分期 F1–F5
论点

一份条件，三个时态

筛选、合集、库的收藏范围看起来是三件事，其实是同一件事在三个时间点上的样子。它们必须共用一套条件结构——而这套结构项目里已经有了：媒体库路由的 library.match_rules 就是它。

筛选

此刻

我现在想看的那一片。低承诺、即时、随时撤销，条件写在 URL 里而不是记忆里。

合集

固化

我决定留下来的那一片。规则不变，命中集随新入库自己生长。

库的收藏范围

入库前

以后这一片该落在哪个库。同一份条件，交给路由去决定新内容的去向。

分期

先做什么，凭什么这么排

智能合集排在手动合集前面：它是筛选的直接固化，边际成本近乎零；手动合集要新增关系表、拖拽排序、多处「加入合集」入口，是独立一期的量。但它一半的价值在 F3 就能拿到——「固定当前这 42 部」一行记录就是快照名单，不必等拖拽。

F1

筛选骨架

条件值对象 + 候选集收窄 + facet 接口；一级四个 chips、计数、URL 同步、四种新排序

验收在 1,000 部的库里勾「动画 + 日本」，墙、索引条、计数三者一致；刷新页面条件还在；清空后回到原墙。

F2

完整筛选

找片 / 查库双栏面板、放宽建议、移动端抽屉、按库类型降级、位置记忆分作用域

验收任意条件组合都不出现空墙；图片库不出现「评分」这种没有事实支撑的控件。

F3

智能合集

合集实体 + 存为合集 + 货架 + 规则条 + 编辑规则倒回筛选条 + 设为库收藏范围

验收筛选 → 存 → 新入库一部命中的片 → 合集数量自动 +1，且规则条的文案与筛选条一致。

F4

手动合集与外延

拖拽排序、详情页与海报悬浮的「加入合集」、跨库合集、TMDB 系列自动合集、Jellyfin 合集映射、分享

验收拖拽出的顺序在海报墙、Jellyfin 客户端、分享页三处完全一致。

F5

个性化与儿童档案

成员级推荐行；把分级从筛选器升级为成员级内容约束——不是筛掉，是根本看不见

验收儿童成员登录后，超分级作品在墙、搜索、合集、Jellyfin 四处均不可见。
