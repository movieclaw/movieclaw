# 刮削与整理个性化：配置菜单设计

> 状态：草案（待评审）。本文把 media_scrape / movieclaw_media.library /
> library.organize 里写死的选图、语言、命名细节开放为面向收藏玩家的
> 配置菜单，并划清"开放什么、不开放什么"的边界。

## 0. 定位与目标

现状（见 `media_scrape.py`、`movieclaw_media/library.py`、
`library/organize.py`）：刮削与整理走"一套固定最佳实践"，可配置面只有
TMDB 环境变量（语言/地区/图片档位）、库级 `write_media_assets` 开关和
条目级手动选图锁。选图策略、命名模板、分级优先级全部写死。

收藏玩家的诉求是**细节可控**：海报要不要中文字、背景图选哪种、文件名里
带不带分辨率与发布组、目录用中文名还是原名。目标：

1. **一个配置菜单管全部刮削细节**——设置页新增「刮削与整理」分区，
   语言、选图、图片质量、命名模板、目录写入集中在此；
2. **约定优于配置**——每个新配置的默认值就是当前写死的行为，升级后
   不配置则一切照旧，零迁移零惊吓（moviebot 稻草人配置的反面教训依旧
   有效：不预留存而不用的配置，本文开放的每一项都有明确消费者）；
3. **改完能生效**——配置变更后引导用户一键整库刷新/重新整理，而不是
   "改了但存量不动"的半吊子。

非目标：多刮削源（豆瓣详情/Fanart.tv/TVDB）不在本文范围——那是数据源
架构议题，仅在 §5 留接口开口；NFO 内容结构不开放（Kodi/Emby 硬规范）。

## 1. 配置分层

```
代码默认值（= 当前行为）
  └─ 全局「刮削与整理」设置（SettingStore，namespace metadata.scrape）
       └─ 库级覆盖（Library 行内 JSON，只覆盖显式设置的字段）
            └─ 条目级手动锁（现有选图锁，粒度最细、优先级最高）
```

- **全局设置**走现有 `SettingStore` 通用表 + 注册表机制（`settings/base.py`），
  新增配置域零数据库迁移；
- **库级覆盖**加在 `library` 表一个可空 JSON 列 `scrape_overrides`（一次
  迁移）：动漫库要日文原名海报、纪录片库要无字背景，这类"按库口味"
  是收藏玩家的真实场景。空对象 = 全跟全局。只允许覆盖 §2 中标注
  〔可库级〕的字段——命名模板允许库级覆盖（电影库与剧集库模板本就
  独立），语言不允许（语言是条目档案属性，同一条目跨库共享一份档案，
  按库切语言会让两库抢写同一行 media_metadata）；
- **环境变量兼容**：现有 `TMDB_LANGUAGE` 等 env 保留为**部署级初始值**
  ——设置域首次读取（库里无该 namespace 行）时以 env 值为默认落库，
  之后以数据库为准，env 仅在设置从未保存过时生效。`get_settings()` 的
  tmdb_* 读取点（media_scrape、media_discover、image_variants）统一改经
  新的 `get_scrape_config()` 异步读取器（带进程内缓存，settings 保存时失效）。

## 2. 配置面清单（即菜单结构）

### 2.1 语言与地区

| 配置 | 类型/默认 | 替代的写死点 |
|---|---|---|
| 元数据语言优先级 | 有序列表（1~3 项），默认 `[zh-CN, en-US]` | `TMDB_LANGUAGE` + `_fetch_english_text` 写死的 en-US 兜底 |
| 分级优先地区 | 有序多选，默认 `[CN, US]` | `_parse_certification` 写死 CN→US |

`TMDB_REGION`（地区）**不进本分区**（用户决策 2026-08-27）：它只消费于
发现页的「正在热映/即将上映」两行与电影筛选（`movieclaw_media/service.py`
的 `region` 参数），是"发现页的院线视角站在哪个国家"，与刮削无关。
它归入独立的「发现页」设置（同为 `SettingStore` 配置域，界面文案改为
用户视角：「决定『正在热映 / 即将上映』显示哪个国家的院线片单」），
不要因为同是 TMDB 参数就混进刮削菜单——按配置的**消费方**归类，
而不是按数据来源归类。

**语言做优先级而不是单选**（用户决策 2026-08-27）：Emby/Plex/Kodi 的
心智模型都是"首选语言 + 回落"，单选 + 独立的"简介兜底语言"是同一
语义的拆散表达，合并成一个有序列表更直观，也与选图的语言优先级（§2.2）
同构。语义与成本：

- **首位 = 请求语言**：TMDB 单次请求只接受一个 `language`，首位决定
  详情/季集请求的语言，也决定类型名、演员译名等只随请求语言走的字段；
- **条目级字段回落零额外请求**：档案请求本就带
  `append_to_response=translations`（现只用于收集别名），标题/简介/
  tagline 的各语言翻译已在同一响应里——主语言缺失时按优先级从
  translations 本地取下一语言即可。现状"简介缺失补拉一次 en-US"
  是它的退化版，改造后那次请求反而省掉；
- **"缺失"按字段判定**：简介/tagline 看空值；标题看 translations 里
  有无该语言的翻译条目（TMDB 对无翻译的标题会自动退回原名，不能拿
  返回值判断）。默认 `[zh-CN, en-US]` 下与现状行为一致：简介兜底
  语义不变，标题回落与 TMDB 自身的回落链等效；
- **季集级回落有闸**：分集标题/简介不在 translations 里，逐集拉翻译
  是每集一次请求，不可接受。规则：某季主语言的分集覆盖率过低（集名
  多为 "Episode N" 占位/简介大面积为空）时，整季按下一语言**重拉一次**
  ——每季每级至多一次请求，且只在刮削管线内生效；
- `media_metadata.scrape_language` 记录首位语言（现状语义不变）。

不开放：别名收集范围（`_ALIAS_REGIONS/_ALIAS_LANGUAGES`）。别名喂的是
匹配内核（种子命名以中英为主），不是展示偏好；开放它只会让用户误伤
自己的识别率。

### 2.2 选图偏好〔可库级〕

**图片语言与文本语言同构**（用户决策 2026-08-27）：TMDB 每张候选图带
`iso_639_1`（null = 无文字烧录），图片的语言选择用与元数据语言完全一致的
**优先级列表**机制，不做散装单选。列表项除具体语言外含三个特殊项：
「跟随元数据主语言」（引用 §2.1 首位，改语言时选图自动跟随）、
「原始语言」（按条目的 original_language 动态解析）、「无文字」（null）。

| 配置 | 类型/默认 | 说明 |
|---|---|---|
| 海报选择 | 二选一，默认「TMDB 默认（与发现页一致）」 | 另一档「按语言优先级挑选」——展开下面的优先级列表；选后接受"订阅前后海报可能跳变"（菜单内注明）。原草案的「本地化优先/原始语言/无文字」三个单选只是该列表的三种预设排序，统一进列表 |
| 海报语言优先级 | 有序列表，默认 `[跟随元数据主语言, en, 无文字]` | 逐级取第一档有候选的语言，档内按分辨率门槛 + 加权票数排序（`_sorted_candidates` 复用） |
| 背景图语言优先级 | 有序列表，默认 `[无文字, 跟随元数据主语言, en]` | 同一机制；"无文字优先"即默认首位，想要带 logo 横图的把语言排到前面即可，原草案的「按票数」单选被列表机制覆盖 |
| 最低分辨率门槛 | 海报/背景两个数字，默认 500/1920 | `_MIN_POSTER_WIDTH` / `_MIN_BACKDROP_WIDTH`；0 = 不设门槛 |
| 图片质量档位 | 海报/背景/剧照三个下拉，默认 w780/original/w300 | `TMDB_POSTER_SIZE` 等三个 env 入菜单；选项列 TMDB 合法档位，注明磁盘占用量级 |

实现注意：候选图请求的 `include_image_language` 须由优先级列表推导
（列表中出现的语言 + null），而不是现在写死的 `null,{语言},en`；
「更换图片」弹层的候选排序（`list_image_candidates`）与自动选图共用
同一份优先级参数，保持"列表第一张 = 自动会选的那张"的既有承诺。

评分公式（`_weighted_score`）不开放——它是防"1 票 10 分"的正确性
机制，不是口味。手动选图锁不变，仍是最高优先级。

### 2.3 命名模板〔可库级〕

**机制选择：受控 token 模板，否决自由模板引擎**（权衡见 §5）。

四个模板（前两个电影库用，后两个剧集库用；花括号 token 渲染后逐段
`sanitize_folder_name`，token 之外的字面文本原样保留）：

| 模板 | 默认值（= 现状） |
|---|---|
| 条目目录 | `{title} ({year})` |
| 电影文件名 | `{title} ({year})` |
| 季目录 | `Season {season:02d}` |
| 剧集文件名 | `{title} ({year}) - S{season:02d}E{episode:02d}` |

可用 token：`title` / `original_title` / `year` / `tmdb_id` / `imdb_id` /
`season` / `episode` / `episode_title` / `resolution` / `media_source` /
`release_group`。数字 token 支持 `:02d` 补零后缀，其余不引入条件/过滤器
语法——需要"字段缺失时不留空括号"的场景由渲染器统一处理（token 为空
时连同紧邻的成对括号与分隔符收缩，规则确定性、有单测）。

校验（保存时前置报错，中文文案）：

- 条目目录模板必须含 `{title}` 或 `{original_title}`；剧集文件名模板必须
  含 `{season}` 与 `{episode}`（否则多集同名互相覆盖）；
- token 渲染值内的 `/` 等保留字符照走 `sanitize_folder_name`，模板字面
  文本中禁止路径分隔符（模板只描述**一段**目录/文件名，层级结构固定为
  `条目目录[/季目录]/文件名`，不开放自定义层级——`entry_dirs` 识别链、
  条目删除、NFO 落点都依赖这个结构假设）;
- 保存前渲染一部内置示例电影 + 一部示例剧集实时预览。

**命名同源约束**（本节的实现红线）：`标题 (年份)` 目前四处共用——
`derive_save_path`（投递 save_path）、`ingest`（入库落名）、`organize`
（整理目标）、`entry_base_name`（镜像/删除的条目目录判定）。模板化必须
收敛到一个新模块 `library/naming.py` 统一渲染，四处全部改读它，**不允许
任何一处继续拼字符串**——否则改了模板后投递落 A 名、整理算 B 名，
strm 回流链路（docs/design/strm-workflow.md）直接断裂。

版本标签（` - 标签` 后缀，`_version_labels` 的分辨率→片源→发布组
递进）不模板化：它是同名冲突时的**追加逻辑**而非命名偏好，且必须保持
确定性幂等。用户想在常规文件名里带分辨率，用 `{resolution}` token 即可。

**模板变更的存量语义**：整理器本就是"算规范名→不一致则改名"的幂等
引擎，模板变更后存量自然全部"待整理"。保存模板时提示"对存量生效
需对各库执行一次整理"，并给一键入口；不自动触发（大库改名是重操作，
用户该看着整理预览确认）。

### 2.4 媒体目录写入〔可库级〕

现有单开关 `write_media_assets` 拆细：

| 配置 | 默认 | 说明 |
|---|---|---|
| 写入图片（poster/fanart/剧照） | 开 | 现状行为 |
| 写入 NFO | 开 | 有人用 Emby 自己刮、只要我们的图 |
| 分集剧照镜像 | 开 | 几百集的剧照是最大的写入量，单独可关 |

`write_media_assets` 列保留为总闸（关 = 三项全关），三个细项进
`scrape_overrides`；镜像的"只增不覆盖不删除 + 资产较新才覆盖"铁律
不开放配置。

### 2.5 明确不开放的

- 刷新分档周期（`next_refresh_delay`）：调快就是打爆 TMDB 限流，
  收藏玩家的诉求里也没有它；
- NFO 文件名与内容结构、镜像图片文件名（Kodi/Emby/Jellyfin 硬规范，
  改了播放器不认）；
- 演员数上限、加权评分公式、原盘目录处理。

## 3. 交互设计

- 设置页新增「刮削与整理」分区（`apps/web` settings-view 加 section，
  与现有分区同构）。分区内**按刮削管线的执行顺序分四个 tab**
  （用户决策 2026-08-27：按"配置的是什么"分类，配置动线跟着数据流走）：
  **① 元数据**（语言优先级、分级优先地区）→ **② 图片**（海报/背景
  语言优先级、门槛、质量档位）→ **③ 命名与整理**（模板 + 实时预览）→
  **④ 目录写入**（镜像开关）。tab 编号即管线顺序，是真实的序列而非装饰；
- 「地区」不在本分区（见 §2.1）——归入「发现页」设置；
- 命名模板卡片：模板输入 + token 快捷按钮 + 双示例实时预览 +
  「恢复默认」；保存后弹条提示"存量文件需整理后生效"带各库整理入口；
- 选图偏好卡片保存后提示"存量图片需整库刷新生效"带刷新入口
  （刷新本就按新配置全量重选重下，`sources.json` 溯源机制已支持）；
- 库编辑弹窗加「高级：覆盖全局刮削设置」折叠区，仅列〔可库级〕字段，
  每字段三态：跟随全局 / 显式值。

测试口径：命名渲染器全分支单测（token 缺失收缩、补零、非法模板拒绝、
默认模板渲染结果与现状字节级一致）；选图策略参数化后原有单测跑默认
参数必须零 diff——**"默认值 = 现状"是本设计最重要的可验证承诺**。

## 5. 权衡与已否决方案

- **Jinja2/自由表达式模板**：能力上限高，但错误信息对非开发者不可读、
  安全面大（沙箱逃逸/无限循环）、且条件语法会让"确定性幂等"难以
  静态保证。受控 token + 收缩规则覆盖 MoviePilot/TMM 用户的绝大多数
  真实模板，超出部分（按分辨率分目录、自定义层级）明确拒绝；
- **条目级命名覆盖**：破坏整理幂等（每条目一套规则，改名结果不可
  预测），且条目级诉求实质是"这部片名字刮错了"——那是识别纠错
  （人工认领）的职责，不是命名配置；
- **多刮削源**：不做，但 §2.2 的选图策略函数保持纯函数、以候选列表为
  输入，未来接 Fanart.tv 只是多一路候选来源，策略与菜单不用动；
- **全局设置直接塞 `Settings`（env 体系）**：否决——收藏玩家的调参
  需要界面即时生效，env 改完要重启容器，与"简单、可调配"背道而驰。

## 6. 分期实施

- **P1 设置域与选图/语言**：`MetadataScrapeSetting` + env 播种 +
  语言/分级/兜底/选图/图片档位接入 + 设置页新分区（不含命名模板、
  不含库级覆盖）。价值即时：换语言、换选图口味、调图片质量全部
  界面化，且无迁移。
- **P2 命名模板**：`naming.py` 渲染器 + 四处接入 + 模板卡片与整理
  联动。含一次"默认模板 = 现状"字节级回归验收。
- **P3 库级覆盖**：`scrape_overrides` 迁移 + 合并读取 + 库编辑弹窗
  折叠区 + 目录写入细分开关。

每期独立可发版，P1 不依赖后两期的任何结构。
