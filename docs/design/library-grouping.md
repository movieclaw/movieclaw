# 媒体库目录分组（首期：按区域 / 按类型）

> 状态：方案评审中，未实现。
> 关联：docs/design/library.md（库的定位）、docs/design/metadata.md（元数据来源）。

## 0. 问题与定位

监听导入 / 订阅投递目前把所有条目扁平落在库主根下（`{主根}/标题 (年份)`），
布局硬编码、不可配置。用户普遍的诉求是按影片特征分目录，如：

```
/media/movies/华语/流浪地球 (2019)/
/media/movies/欧美/奥本海默 (2023)/
```

**核心设计决策：分组是「媒体库目录布局」的属性，挂在库上，不挂在监听规则上。**
理由：全项目有四个写/读路径的地方共用同一套布局约定——

| 消费点 | 位置 | 分组后的行为 |
|---|---|---|
| 订阅/手动投递 save_path | `library_config.derive_save_path` | 落 `{主根}/{分组}/{条目}` |
| 监听导入落位 | `library_ingest`（经 derive_save_path） | 同上，自动跟随，**监听规则零改动** |
| 整理器规范路径 | `library_organize._build_plan_sync` | 目标含分组层 → 顺带成为**布局迁移工具** |
| 扫描条目判定 | `library_import.entry_dirs` | 从设计之初就兼容分组层（`{root}/大陆/风筝 (2017)/`），**零改动** |

若把规则挂在 import_watch 上，整理器与监听导入会按两套布局互相搬家。
库是布局的唯一所有者，这也与 import_watch 模块头"媒体库只有一套目录
体系"的既有决策一致。

## 1. 产品形态

### 1.1 分组方式（首期三选一，库级设置）

| 选项 | 值 | 目录效果 | 依据字段（media_metadata） |
|---|---|---|---|
| 不分组（默认） | `none` | `{主根}/标题 (年份)` | — |
| 按区域 | `region` | `{主根}/华语\|日韩\|欧美\|其他/标题 (年份)` | `origin_countries` |
| 按类型 | `genre` | `{主根}/动画\|纪录\|动作\|剧情…/标题 (年份)` | `genres` |

- 默认 `none`，存量库升级无感；
- 分组只作用于**根与条目目录之间**这一层。条目目录名与文件名
  （`标题 (年份)`、`SxxEyy`、多版本标签）不开放定制——它们是
  Emby/Plex/Jellyfin 识别约定和扫描/多版本归组的公共前缀；
- 年代分组价值有限，不做；自定义映射/组合模板留待后续（见第 6 节）。

### 1.2 分组取值规则（必须确定性，整理器重跑不许来回搬家）

两种分组统一用一套机制：**有序规则表，首个命中生效，末位兜底「其他」**。

**按区域**（内置映射，首期不可编辑）：

| 分组（按声明顺序匹配） | 国家码（origin_countries，ISO-3166-1） |
|---|---|
| 华语 | CN、HK、TW、MO、SG |
| 日韩 | JP、KR |
| 欧美 | US、GB、FR、DE、IT、ES、PT、NL、BE、SE、DK、NO、FI、IE、AT、CH、PL、CZ、RU、UA、GR、HU、RO、CA、MX、BR、AR、AU、NZ |
| 其他 | 兜底（印度/泰国/伊朗等，及元数据缺失） |

匹配规则：按分组声明顺序遍历，条目的 `origin_countries` **任一**国家码命中
该分组即归入。中美合拍（CN+US）→ 华语（华语声明在前），确定性由声明
顺序保证，与多国排列顺序无关。

**按类型**：

| 分组（按声明顺序匹配） | 规则 |
|---|---|
| 动画 | genres 含「动画」 |
| 纪录 | genres 含「纪录」 |
| （首个类型名） | 其余条目取 `genres[0]` 原文（TMDB zh-CN 已是中文：动作/喜剧/科幻/剧情…） |
| 其他 | genres 为空 |

动画/纪录前置的原因：TMDB 的 genre 排序常把「剧情」放第一位，不前置
会导致"剧情"巨型分组，而"把动画单独分出来"恰是此类用户的核心诉求。

**元数据缺失**：遵守三态铁律，落「其他」——不阻塞入库；元数据刷新
到位后跑一次整理即归位。分组名统一过 `sanitize_folder_name`。

## 2. 交互设计（体验重点：让用户"看到"分组的价值）

### 2.1 设置入口：媒体库表单弹窗（LibraryFormDialog）

在「根路径」区块之后新增「目录分组」区块，新建与编辑共用：

```
┌─ 添加媒体库 ────────────────────────────────┐
│ 库类型   [电影] [剧集]                        │
│ 名称     [电影库____________]                 │
│ 根路径   /media/movies              [主根]    │
│                                              │
│ 目录分组                                      │
│ [不分组] [按区域] [按类型]      ← 胶囊单选，   │
│                                   与库类型同款 │
│ ┌─ 入库效果预览 ──────────────────────────┐  │
│ │ /media/movies                           │  │
│ │ ├── 华语                                │  │
│ │ │   └── 流浪地球 (2019)                 │  │
│ │ ├── 日韩                                │  │
│ │ │   └── 铃芽之旅 (2022)                 │  │
│ │ ├── 欧美                                │  │
│ │ │   └── 奥本海默 (2023)                 │  │
│ │ └── 其他                                │  │
│ │     └── 三傻大闹宝莱坞 (2009)           │  │
│ └─────────────────────────────────────────┘  │
│ 新入库内容按上面的结构落盘；监听导入与订阅     │
│ 下载自动跟随，无需单独配置。                   │
│                                              │
│                        [取消]  [保存]         │
└──────────────────────────────────────────────┘
```

交互细则：

- **即点即览**：切换分组选项，预览树立即重渲染（短淡入过渡）。
  「不分组」同样渲染扁平树——用户来回点选就能直观对比，价值感知
  靠"看见差异"而非文案说教；
- **树根用真实主根路径**：已选根路径时树根显示真实路径（保尾截断，
  与根路径行同款 dir=rtl 手法）；尚未选根时显示占位「媒体库根目录」，
  预览不因此隐藏——让用户在配置早期就看到分组长什么样；
- **示例条目按库类型出**：电影/剧集各一组内置示例（见 2.3），剧集示例
  条目下多画一层 `Season 01`，与真实落盘一致；
- **等宽字体 + 现有玻璃面板样式**（`glass` 系列），树最多展示 4 组、
  每组 1–2 个条目，高度固定不滚动——它是"效果示意"，不是文件浏览器。

### 2.2 编辑已有库：预览用真实数据，迁移走整理器

**真实分布预览**：编辑一个已有在账条目的库时，预览不再用内置示例，
而是展示**这个库真实的分组分布**（数据来源见 3.3）：

```
│ ┌─ 入库效果预览（基于库内 167 部影片）────────┐
│ │ /media/movies                              │
│ │ ├── 华语 · 36 部                           │
│ │ │   ├── 让子弹飞 (2010)                    │
│ │ │   └── 流浪地球 (2019) …                  │
│ │ ├── 日韩 · 21 部                           │
│ │ │   └── 小偷家族 (2018) …                  │
│ │ ├── 欧美 · 105 部                          │
│ │ │   └── 奥本海默 (2023) …                  │
│ │ └── 其他 · 5 部（含元数据缺失 2 部）        │
│ └────────────────────────────────────────────┘
```

"你的 167 部影片会分成这四组、各多少部"比任何示例都有说服力，也把
「其他」兜底组的规模提前亮给用户，避免执行后才发现意外。

**保存后的存量迁移**：保存只改"新内容的落位"，绝不在保存动作里搬文件。
分组发生变更且库内有在账文件时，保存成功后弹窗不直接关闭，切换为
收尾面板：

```
┌─ 分组已更新 ─────────────────────────────────┐
│ ✓ 之后的新入库内容将按「按区域」分组落盘。      │
│                                              │
│ 库内现有 167 个文件仍在原位置。可通过「整理」   │
│ 按新分组归位（先预览每个文件去向，确认后执行）； │
│ 不整理也不影响使用：扫描与播放器识别照常。      │
│                                              │
│                  [稍后再说]  [立即整理归位]     │
└──────────────────────────────────────────────┘
```

「立即整理归位」直接打开现有 `LibraryOrganizeDialog`——预览/风险告知/
进度/结果四段式流程原样复用，整理预览里每条 `source_rel → target_rel`
天然展示了分组迁移去向（如 `奥本海默 (2023)/… → 欧美/奥本海默 (2023)/…`），
零新增交互。「稍后再说」关闭弹窗，用户随时可从库卡片菜单进整理。

### 2.3 内置示例条目（新建库 / 空库的预览数据）

选取知名、区域与类型分布均衡的条目，写死在后端预设里（与映射表同源，
保证示例的分组结果永远和真实逻辑一致）：

- 电影：流浪地球 (2019)〔华语/科幻〕、奥本海默 (2023)〔欧美/剧情〕、
  铃芽之旅 (2022)〔日韩/动画〕、三傻大闹宝莱坞 (2009)〔其他/喜剧〕；
- 剧集：漫长的季节 (2023)〔华语〕、最后生还者 (2023)〔欧美〕、
  孤独的美食家 (2012)〔日韩〕、行星 (2019)〔纪录〕。

## 3. 技术方案

### 3.1 数据模型

`Library` 加一列（alembic 迁移，默认值兜底存量）：

```python
# none=不分组 / region=按区域 / genre=按类型；创建后可改，
# 改后存量迁移是整理器的职责（保存不搬文件）
group_by: str = Field(default="none", description="目录分组：none / region / genre")
```

不新增映射配置表——首期映射是代码内常量（`library_layout.py`），
不做"存而不用"的配置（moviebot 稻草人配置的教训）。

### 3.2 路径推导：单一函数收口

新增 `library_layout.py`（或并入 library_config）：

```python
def group_segment(library, metadata: MediaMetadata | None) -> str | None:
    """条目的分组目录名；不分组返回 None。确定性：有序规则表首个命中。"""

def derive_entry_dir(library, item, metadata) -> str | None:
    """{主根}/[{分组}/]{标题 (年份)}——derive_save_path 的升级版。"""
```

四个消费点改造：

1. **投递**（`download_dispatch` / `downloaders` 路由手动推送）：
   改用 `derive_entry_dir`。投递时条目已建档、metadata 已拉齐，无时序
   问题；metadata 意外缺失落「其他」；
2. **监听导入**（`library_ingest.py:401`）：同上，一处改动；
3. **整理器**（`library_organize._build_plan_sync`）：计划查询 join
   `MediaMetadata`，目标路径在**文件当前所在根**下加分组段（分组层
   跨根同构，不跨根迁移的既有约束不变）。`_move_no_clobber` 的
   os.link 防覆盖、空目录清理（旧分组目录搬空后被 `_prune_emptied_dirs`
   顺带收走）、幂等性全部免费复用；
4. **扫描**：`entry_dirs` 已兼容分组层，条目删除的目录判定也已按条目
   目录（而非库根直接子目录）计算——零改动，回归测试覆盖即可。

### 3.3 API

- `LibraryPayload` / 库响应模型增加 `group_by`；
- 新增预览接口（供 2.1/2.2 的效果预览）：

```
GET /api/libraries/grouping-preview?kind=movie&group_by=region[&library_id=3]
→ { "groups": [ { "name": "华语", "count": 36, "samples": ["让子弹飞 (2010)", …] }, … ],
    "unknown_count": 2 }        # 元数据缺失、落「其他」的数量
```

不带 `library_id`（新建库）返回内置示例条目的分组结果（count 为 null，
前端不显示数量）；带 `library_id` 时对该库在账条目 join metadata 实时
聚合（百级条目内存聚合毫秒级，无需缓存）。分组定义只存在于后端一处，
前端纯渲染——示例与真实逻辑永不漂移。

### 3.4 前端改造点

| 文件 | 改动 |
|---|---|
| `library-view.tsx`（LibraryFormDialog） | 「目录分组」胶囊单选 + 预览树组件 + 保存后收尾面板 |
| 新组件 `grouping-preview.tsx` | 目录树渲染（等宽/玻璃面板/淡入），消费预览接口 |
| `lib/api/libraries.ts` | `group_by` 字段、`previewGrouping()` |
| 库详情页设置入口 | 复用同一弹窗，无独立改动 |

## 4. 边界与明确不做的事

- **不迁移不是坏状态**：旧内容留在原位可正常扫描/播放/订阅补全，
  分组只影响新入库落位——文案与交互都按"整理是可选优化"表达；
- **监听规则不加任何分组配置**；同库不同来源不同布局，无合理场景；
- **条目目录名/文件名模板不开放**（理由见 1.1）；
- **BDMV 原盘目录**：整理器现有"整体保持原结构"的跳过规则不变，
  首期原盘不参与分组迁移（新入库的原盘照常落分组目录）；
- **写盘资产（NFO/海报）**：随条目目录整体移动（附属文件跟随机制
  已覆盖同目录文件），无需特殊处理。

## 5. 验证标准（目标驱动）

1. `group_segment` 单元测试：区域映射（含中美合拍取声明序）、动画/纪录
   前置、genres 空落其他、metadata 为 None 落其他、分组名 sanitize
   → 全部通过；
2. `derive_entry_dir`：三种 group_by 的路径拼接 + 无根返回 None → 通过；
3. 监听导入集成测试：region 库落 `{主根}/华语/条目/` → 通过；
4. 整理器：扁平库改 region 后计划含分组迁移、**连跑两轮第二轮零动作**
   （幂等）、旧条目空目录被清理 → 通过；
5. 投递 save_path 含分组段 → 通过；
6. 预览接口：无 library_id 返回示例、有 library_id 返回真实分布与
   unknown_count → 通过；
7. alembic 升级后存量库 group_by=none，全链路行为与升级前一致 → 通过。

## 6. 后续演进（本期不做）

- 自定义分组映射（用户编辑分组名与国家码/类型集合，有序规则表机制不变）；
- 组合模板（`{区域}/{年代}` 等 token 模板）；
- 「其他」组的条目清单页（点预览里的分组直接看都有谁）。
