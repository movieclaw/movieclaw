# 持久化后台任务

## 目标与边界

MovieClaw 的 Web、CLI、Agent 和调度器必须看到同一份后台任务状态。任务一旦被
服务端接受，即使页面离开、CLI 退出、应用重启或进程崩溃，也不能丢失；用户可以
用稳定 `job_id` 查询、等待、取消、重试并查看事件时间线。

这里的 Job 只承载用户可感知、需要追踪的异步业务。定时触发定义继续使用
`scheduled_task`，定时器的一次触发可以创建 Job；文件监听、缓存预热、SSE 心跳等
临时协程不进入 Job 表。

当前原生接入 AI 字幕生成（含 PGS OCR）、媒体库扫描、整库/单条目元数据刷新、
媒体库整理、条目转移、监听入库和整库/单条目章节生成。字幕领域不再保留独立状态、停止接口或意图文件；
媒体库旧进度接口只作现有页面的兼容投影，查询、等待、取消、重试与历史统一以 Job
为事实源。

## 数据模型

- `job`：任务定义、状态、进度、结论、错误、租约、来源、审计与保留期。
- `job_resource`：任务到 `library`、`media_item`、`library_file` 等资源的多对多索引。
  媒体墙因此可以一次查询整库任务，不做逐文件 N+1 轮询。
- `job_event`：每次状态/进度变化的持久化时间线，`id` 是 SSE 续传游标，
  `(job_id, revision)` 唯一。
- `job_lock`：执行期资源锁。锁只在真正执行时获取，不与语义去重混用。

大断点不塞进 SQLite。字幕逐块翻译断点和 OCR 缓存继续位于 `data/`；Job 只保存小型
进度与断点引用。清理 Job 历史不会删除媒体产物。

## 状态机

```text
queued ──► running ──► succeeded
   │           ├────► retry_wait ──► running
   │           ├────► blocked
   │           ├────► failed
   │           └────► cancelling ──► cancelled
   └───────────────────────────────► cancelled
```

`waiting` 预留给父子任务等待；`blocked` 表示需要用户补配置或输入，不伪装成普通
失败。活跃状态为 `queued/running/retry_wait/cancelling/waiting/blocked`，终态为
`succeeded/failed/cancelled`。

公共进度包含 `mode`（确定/不确定/等待/暂停）、阶段、用户文案、可选的分子分母和
百分比、阶段序号以及领域 `details`。无法计算时 `percent=null`，不展示虚假进度。

## 投递、去重与并发

领域接口做同步预检，然后在数据库中创建 Job，返回 `202 Accepted`、完整 Job 视图、
`Location: /api/v1/jobs/<id>`。执行永远异步；“等待完成”只是客户端行为。

`dedupe_key` 判断两个请求是否在做同一件事，字幕键由文件和输出语言组合而成。SQLite
部分唯一索引保证同一 dedupe key 最多有一个活跃任务，跨进程并发也不会重复消费。
`conflict_policy` 决定返回已有任务、拒绝或排队。

执行器领取任务后才按排序后的资源键原子获取 `job_lock`，避免多资源死锁。当前单体
进程默认最多同时领取 4 个 Job；字幕自身的模型请求仍按领域并发控制，在遇到限流时
自动降频。任务租约 45 秒、15 秒续租；每次领取都有独立令牌，过期执行不能再写入
进度或结果。所有存活实例都会周期检查过期租约，因此不需要整个服务重启才恢复。

## 恢复与停机

正常停机先取消执行协程，把本实例持有的 Job 和锁在同一事务中退回 `queued`，再关闭
LLM、文件监听与数据库。异常崩溃依赖租约自愈。字幕断点已逐块落盘，因此恢复不会
重花已完成块的模型费用。

服务重启不是业务失败，不增加 `attempt`，因此连续应用更新不会耗尽异常重试额度。
整库元数据刷新每三个条目提交一个进度检查点；整理与转移保存用户确认后的精确路径
计划，可修复“磁盘已改名/发布、台账尚未提交”的窗口。跨盘转移复制到目标旁的隐藏
临时路径，按已复制字节续传，全部完成后才原子发布；更新发生在发布与删除源之间时，
发布标记允许新进程安全完成收尾，且始终不覆盖既有目标。

媒体库扫描以逐文件提交的库存台账作为恢复检查点。更新后重新盘点目录，已完成路径按
增量语义直接跳过，当前未完成文件允许幂等重跑；不持久化一份会随磁盘变化而过期的
路径快照。收尾的图片资产阶段是唯一按"本轮识别的条目"取目标的一段，重启后那批条目
已成秒过行、不会再被算作本轮识别，因此续跑的这一轮按"本库已识别但还没有本地主图"
把它们捞回来补齐（判据是上一轮留在进度里的 identified，正常扫描不多扫这一趟）。
章节生成的补缺模式同样以台账为检查点，force 重抓因为每一行都要重做，改用进度里的
文件游标续跑；两种模式的进度都按整轮作业累计，重启后不从 0 重数。盘点、入账、介质补探和图片资产四个阶段的观察进度节流写入 Job。写进度前
先提交扫描主会话，保证 SQLite 中“领域事实先于观察进度”，也避免两个写事务互锁。
文件监听和六小时对账仍保持轻量直接触发，不制造大量 Job 历史，但会检查同一库的
活跃 Job 与资源租约；有用户作业时自动让路，由后续文件事件或对账补齐。

监听入库的 watchdog 与兜底巡检也只负责完成检测和创建 `library.ingest`，不在监听
协程内搬运。Job 重新核对下载器状态、进行中标记和磁盘现场后再识别、路由与落位；
指定库在入队时声明资源，自动路由在识别成功后动态补充目标库并取得同一资源锁。
跨盘复制写到目标旁的隐藏续传文件，边车固定源路径、大小与修改时间，更新后从现有
字节继续，源版本改变则丢弃旧断点，完整后才原子发布。识别不出进入 `blocked`，用户
在监听清单认领后原地恢复同一个 Job，保留稳定 ID、事件时间线与复制断点。

Job 是任务意图和运行状态的唯一事实源；领域目录只保存可复用的翻译检查点和 OCR
缓存，不保存第二份任务状态。恢复时沿用创建时固定的输入、供应商和模型引用。字幕
任务还固定预检时参考源的大小与修改时间；排队期间源文件变化时停止并要求重新预检，
不会静默翻译另一份内容。处理器显式声明支持的 `definition_version`；升级后不兼容的
旧定义会清晰失败并释放去重键，不靠隐式字段兼容或让处理器带着旧输入冒险执行。

## API 与 CLI

- `GET /jobs`：按状态、类型、资源查询。
- `GET /jobs/{id}`：详情。
- `GET /jobs/{id}/wait`：按 revision 长轮询，最长 30 秒。
- `GET /jobs/{id}/events`：事件时间线。
- `POST /jobs/{id}/cancel`：协作式取消。
- `POST /jobs/{id}/retry`：失败/取消任务以原输入新建并保留
  `retry_of_job_id`；`blocked` 任务原地恢复入队，保留稳定 ID 且不绕过去重约束。
- `GET /jobs/stream`：前端全局 SSE。
- `GET /jobs/health`：执行器、队列和最老等待时间。

`mclaw jobs list/show/wait/cancel/retry/events/health` 与 API 同源。领域开始接口通过
OpenAPI 的 `x-cli-job.id_path` 告诉 CLI 从响应哪里取得 Job ID。开始命令默认
`--no-wait`，适合 Agent 和脚本；显式 `--wait` 或 `mclaw jobs wait <id>` 才持续等待。
Ctrl-C/等待超时只结束本地等待，不取消服务端任务。

## 前端

`JobsProvider` 登录后并行加载“全部活跃任务 + 最近历史”，SSE 事件触发合并刷新，15 秒
轮询和窗口回焦兜底。首次 SSE 从当前事件尾部订阅，断线才按游标续传，避免每次打开
页面回放全部历史。侧栏任务中心统一展示来源、阶段、进度、错误与结构化处理动作。
媒体库通过 `job_resource` 聚合：库头显示任务数，关联 `media_item` 的海报直接点亮；
文件详情中的字幕按钮也订阅同一状态，因此 CLI 发起后无需刷新页面即可看到进展。

## 审计、错误与保留

Job 记录发起主体、来源（Web/CLI/Agent/调度器）、定义/处理器/提示词修订号和实际
供应商模型引用，但永不保存 API key；入队层会递归拒绝常见凭据字段。新字幕任务固定创建时选择的模型；配置被删除
时进入 `blocked`，不会静默换模型继续。

错误返回结构化 `code/message/details/actions`，动作包括重试、打开设置、查看日志和
交给 Agent。成功历史保留 30 天，失败/取消保留 90 天；执行器启动时和每小时清理
到期台账。`usage` 已作为统一字段预留，后续把模型 token、请求次数、限流次数和 OCR
图片数接入同一成本口径。

## 验证清单

- Alembic 从空库升级到 head，且只新增表/索引。
- 活跃任务并发去重，资源查询正确。
- 进度、结果和事件事务性持久化。
- 正常停机退回队列，重启后不消耗 attempt 并完成。
- 元数据刷新从完整批次检查点继续，已完成批次不重复。
- 扫描更新后重新盘点并跳过已入账文件，取消时保留已完成台账与最后进度。
- 整理/转移在磁盘变化后、台账提交前重启时能补齐台账。
- 跨盘转移从隐藏临时文件现有字节继续，最终路径只在完整复制后出现。
- 监听巡检只创建 Job；复制中停机保留断点，重启从现有字节继续。
- 监听条目待认领时进入 blocked，认领后复用同一 job id 完成。
- 排队任务取消后不会执行。
- Job API 的列表、等待、事件和取消契约可用。
- CLI 根据 Job 状态而非领域进度字段判定终态。
- Web 类型检查、生产构建通过。
