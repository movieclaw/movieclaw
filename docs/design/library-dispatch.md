# 媒体库自动分派（按区域/类型隔离多个媒体库）

> 状态：方案评审中，未实现。
> 取代：曾提议的"库内目录分组"方案（已废弃）——分类的真实目的不是在
> 一个库里分子目录，而是**隔离出多个媒体库**（华语电影库/日韩剧集库/
> 动漫库各自成库，在 Emby/Plex 里也各自成库、独立展示与授权）。
> 关联：docs/design/library.md、docs/design/metadata.md。

## 0. 问题重述与设计定位

用户的目录组织模型是"一个语种/题材一个库"：

```
/media/movies-cn    → 华语电影库（Emby 里独立一个库）
/media/movies-west  → 欧美电影库
/media/anime        → 动漫库
```

而现状里所有自动入库路径都只认"一个目标"：

- 订阅/手动下载 → 该类型的**默认库**（`resolve_for_subscription`）；
- 监听导入 → 规则里**固定指到一个库**（`import_watch.library_id`）。

多库隔离的用户被迫为每个库单独建监听目录、在下载器里手工选分类，
或者事后手动搬——"识别出影片是什么之后，自动送进对的库"这一步缺失。

**核心设计：给媒体库声明「收录条件」，入库时按条目元数据自动分派。**
库本来就是"我拥有哪些内容、放在哪里"的权威定义（library.md），
收录条件是这个定义的自然延伸："**什么样的**内容放在哪里"。分派逻辑
收口一处，订阅投递、手动推送、监听导入三个入口共用；默认库天然成为
"什么条件都不命中"的兜底——现有概念一个不废。

从废弃方案沿用的资产：分类内核（区域映射表、有序规则、确定性取值）、
"预览式价值感知"的交互思想、元数据基础（`media_metadata` 已持久化
`origin_countries` / `genres`，零新增采集）。

## 1. 核心概念：库收录条件

### 1.1 条件维度（首期两维，均可选）

| 维度 | 取值 | 依据字段 |
|---|---|---|
| 区域 | 华语 / 日韩 / 欧美 / 其他（多选） | `origin_countries` → 内置映射 |
| 类型 | TMDB 类型名多选（动画、纪录、恐怖…） | `genres` |

- 区域映射沿用既定常量表：华语（CN/HK/TW/MO/SG）、日韩（JP/KR）、
  欧美（US/GB/FR/DE/IT/ES/PT/NL/BE/SE/DK/NO/FI/IE/AT/CH/PL/CZ/RU/UA/
  GR/HU/RO/CA/MX/BR/AR/AU/NZ 等约 30 国）、其他（兜底，含元数据缺失）。
  条目多国合拍时按"华语→日韩→欧美"声明序取首个命中，确定性与排列无关；
- 一个库可以只设区域（华语电影库）、只设类型（动漫库）、或两维都设
  （日本动画库 = 区域[日韩] AND 类型[动画]）；两维之间是 AND，
  维度内多值是 OR；
- **不设任何条件 = 普通库**，行为与今天完全一致。整个功能对不需要
  多库隔离的用户不可见（与监听导入同一产品哲学）。

### 1.2 分派解析（确定性，用户不需要排优先级）

给定已识别条目（kind + metadata），在同 kind 的库里按**固定特异度**
取第一个命中：

```
1. 双维库（区域与类型同时命中）     ← 最具体
2. 仅类型库（类型命中）
3. 仅区域库（区域命中）
4. 该 kind 的默认库                ← 兜底，永远存在
```

- **类型优先于区域**是刻意决策：日本动画同时命中"日韩"和"动画"，
  建动漫库的用户意图就是把动画从区域库里拆出去；反向没有合理场景；
- **同层不会撞车，由写入侧校验保证**：同 kind 内，同一个区域值/类型值
  只允许被一个库认领。保存时冲突直接报错（"区域「华语」已被
  『华语电影库』认领"），运行时不存在歧义，也就不需要让用户理解和
  维护优先级——这是本方案能保持简单的关键；
- 元数据缺失（三态 NULL）：区域按"其他"参与匹配，类型不命中任何
  类型条件——通常落到默认库，元数据刷新后新内容自动走对，存量见第 5 节。

## 2. 三个入口的接入方式

### 2.1 订阅 / 手动下载：分派升级"默认选中"，显式选择永远优先

- 订阅弹窗 / 下载目标弹窗打开时，默认库的计算从 `defaultLibraryFor(kind)`
  升级为 `resolve(kind, metadata)`——条目建档时元数据已拉齐，无时序问题；
- 用户**没动**库选择 → 订阅存 `library_id = NULL`，投递时实时按规则解析
  （规则后来变了，未投递的订阅自动跟上）；用户**手动改选** → 存显式
  `library_id`，规则永远让位于人的选择——这与现有
  `resolve_for_subscription`（显式优先，否则默认库）的语义完全同构，
  只是"否则"分支里插入了规则解析；
- 显式挂的库被删除 → 外键 SET NULL，自然回落到规则分派（现有回落
  机制照常工作）。

### 2.2 监听导入：目标库支持「自动分派」

`import_watch` 规则的目标从"固定库"扩展为二选一：

- **指定库**（现状，默认）：行为不变；
- **自动分派**：识别出条目后按第 1 节规则路由。模型上
  `library_id` 置空 + 新增 `kind` 列（movie/tv）——现在识别链的类型
  取自目标库，自动模式下必须由规则自己声明监听的是电影还是剧集；
- hardlink 同盘检测调整：自动模式下保存时对该 kind **所有可能目标库**
  的主根做 st_dev 检测，任一不同盘即阻止保存并提示改用 copy（分派结果
  逐条目而异，运行时才发现跨盘会让部分影片入库失败，前置到保存时）；
- 落位路径不变：`{目标库主根}/标题 (年份)[/Season NN]/…`——不再有
  分组子目录层，`derive_save_path` 无需改动。

### 2.3 分派发生在识别成功之后

无法识别的条目走监听导入现有的失败/重试/手动认领流程，与本功能无关；
分派永远以已锚定的 `media_item` + `media_metadata` 为输入。

## 3. 交互设计

### 3.1 建库弹窗：收录条件区块 + 即时分派反馈

在「根路径」之后新增区块（默认不设条件，普通用户零打扰）：

```
┌─ 添加媒体库 ────────────────────────────────┐
│ 库类型   [电影] [剧集]                        │
│ 名称     [华语电影库________]                 │
│ 根路径   /media/movies-cn           [主根]    │
│                                              │
│ 收录条件（可选）                              │
│ 只有符合条件的内容会自动入这个库；             │
│ 不设条件则作为普通库使用。                     │
│ 区域  [华语✓] [日韩] [欧美] [其他]            │
│ 类型  [动画] [纪录] [＋更多类型]              │
│                                              │
│ ┌─ 分派效果 ──────────────────────────────┐  │
│ │ ✓ 会进入本库：流浪地球 (2019)、          │  │
│ │   让子弹飞 (2010)                        │  │
│ │ ✗ 不进入：奥本海默 (2023) → 电影库(默认) │  │
│ │   铃芽之旅 (2022) → 动漫库               │  │
│ │ 现有库存中约 36 部影片符合本库条件        │  │
│ └─────────────────────────────────────────┘  │
│                        [取消]  [保存]         │
└──────────────────────────────────────────────┘
```

交互细则：

- **区域/类型都是 chips 多选**，与库类型胶囊同款视觉；类型 chips 先展示
  动画、纪录两个高频项，「＋更多类型」展开该 kind 的完整 TMDB 类型表；
- **即点即览**：条件一变，分派效果卡实时刷新，三段信息——
  1. 内置示例条目的正反两面（"会进/不进 + 不进的去哪"），价值感知
     靠"看到边界"；示例条目与分派结果都由后端算出，与真实逻辑同源；
  2. 真实库存统计（系统已有条目时）："现有库存中约 36 部符合条件"；
  3. **冲突即时提示**：勾选已被认领的值立即红字（"「华语」已被
     『华语电影库』认领"），保存按钮置灰——冲突在配置时暴露，
     不留到运行时；
- **快捷模板降低发现成本**：库页「添加媒体库」入口提供预设——
  `华语电影库` / `日韩剧集库` / `动漫库` / `纪录片库`，一键带出
  名称+类型+条件（根路径仍需用户选）。空态引导同步提及"可按区域/
  类型建多个库，内容自动分流"。

### 3.2 分派总览：媒体库页的"入库去向"一览

多库隔离后用户最关心"一部片下下来会进哪个库"。媒体库页顶部加一张
可折叠的总览条（数据由库列表的收录条件前端拼装，零新接口）：

```
入库分派   电影：动画 → 动漫库 ｜ 华语 → 华语电影库 ｜ 其余 → 电影库(默认)
          剧集：日韩 → 日韩剧集库 ｜ 其余 → 剧集库(默认)
```

监听导入设置里选「自动分派」时展示同一张总览，所见即所得。

### 3.3 订阅/下载弹窗：让"自动匹配"可见、可改

默认选中的库旁加说明徽标：`自动匹配 · 华语`（tooltip：按影片区域/类型
自动选择，可手动更改）。用户由此知道系统替他做了什么、依据是什么、
以及随时可以推翻——自动化的信任感来自可解释与可撤销。

## 4. 技术方案

### 4.1 数据模型（alembic 迁移，存量全部无感）

```python
# Library 新增（NULL=不限该维度；两维都 NULL=普通库）
intake_regions: list | None   # 认领的区域组名，如 ["华语"]
intake_genres:  list | None   # 认领的 TMDB 类型名，如 ["动画"]

# ImportWatch 调整
library_id: int | None        # 置空=自动分派（现状规则不变仍指库）
kind: str | None              # 自动分派时必填：识别按此类型走
```

区域映射表是代码内常量（`library_dispatch.py`），首期不做自定义映射
配置——不预留稻草人配置（library.md 第 1 节教训）。

### 4.2 分派器：单一函数收口

新增 `services/library_dispatch.py`：

```python
def region_of(metadata: MediaMetadata | None) -> str:
    """条目的区域组名（华语/日韩/欧美/其他）；确定性：映射表声明序首个命中。"""

async def resolve_library(session, kind, item) -> Library | None:
    """按收录条件分派：双维命中 > 类型 > 区域 > 默认库。查询该 kind 全部库
    后内存匹配（库数量个位数，无需索引设计）。"""
```

消费点改造（三处，均为"默认分支插入规则解析"）：

| 消费点 | 改动 |
|---|---|
| `LibraryConfigService.resolve_for_subscription` | 显式 library_id → **规则分派** → 默认库 |
| `downloaders` 路由（手动推送预检） | 同上；响应带上分派原因（前端徽标用） |
| `library_ingest`（自动分派模式的规则） | 识别成功后调 `resolve_library` 得目标库 |

写入侧校验（`library_config` 保存钩子）：同 kind 内区域值/类型值的
认领唯一性；`import_watch_config`：自动模式的 kind 必填 + 多库同盘检测。

### 4.3 API

- 库 payload/响应加 `intake_regions` / `intake_genres`；
- 新增分派预览接口（建库弹窗的效果卡）：

```
GET /api/libraries/dispatch-preview?kind=movie&regions=华语&genres=[&exclude_library_id=3]
→ { "samples_in":  ["流浪地球 (2019)", "让子弹飞 (2010)"],
    "samples_out": [ {"title": "奥本海默 (2023)", "dest": "电影库（默认）"}, … ],
    "matched_count": 36,                       # 现有库存中符合条件的条目数
    "conflicts": [ {"value": "华语", "library": "华语电影库"} ] }
```

编辑既有库时带 `exclude_library_id` 把自己排除出冲突检测。示例条目
内置于后端（电影：流浪地球/奥本海默/铃芽之旅/三傻大闹宝莱坞；剧集：
漫长的季节/最后生还者/孤独的美食家/行星），分派结果实时用真实逻辑算，
示例与实现永不漂移。

- `import_watch` payload：`library_id` 可空 + `kind`。

### 4.4 前端改造点

| 文件 | 改动 |
|---|---|
| `library-view.tsx`（LibraryFormDialog） | 收录条件 chips + 分派效果卡（消费 dispatch-preview）+ 快捷模板入口 |
| `library-view.tsx`（库页） | 顶部分派总览条（folded，纯前端拼装） |
| `import-watch-section.tsx` | 目标库选择加「自动分派」项 + kind 选择 |
| `subscribe-dialog.tsx` / `download-target-dialog.tsx` | 默认库改走分派结果 + 自动匹配徽标 |
| `lib/api/libraries.ts` / `import-watch.ts` | 新字段与 `previewDispatch()` |

## 5. 边界与明确不做的事

- **条件变更/新建条件库不迁移存量**：跨库大概率跨盘（复制不是改名），
  且涉及"源库台账销账 + 目标库重新入账"的双库一致性——首期明确不做
  自动迁移，只影响新入库内容。文档给出手动路径：把条目目录挪到目标库
  根下 → 目标库扫描入账 → 源库扫描/对账标缺失。"跨库迁移"若有真实
  需求，后续作为独立功能设计；
- **库内分组子目录不做**：被本方案取代。若未来出现"单库 + 子目录"的
  真实诉求，分类内核（区域映射/确定性规则）原样可复用；
- **不做自定义区域映射与规则表达式**：四个区域组 + TMDB 类型多选覆盖
  绝大多数隔离场景，自定义映射留待被真实需求逼出来；
- **默认库不变量不动**：每 kind 至多一个默认库、删除让位等 Repository
  既有逻辑原样保留，它就是分派的兜底。

## 6. 验证标准（目标驱动）

1. `region_of`：多国合拍取声明序、metadata 为 None 落「其他」→ 通过；
2. `resolve_library`：双维 > 类型 > 区域 > 默认库四层特异度、日本动画
   进动漫库不进日韩库、无任何条件库时行为与现状全等 → 通过；
3. 认领唯一性校验：同 kind 重复认领同一区域/类型值被拒、不同 kind
   互不影响、编辑自身不误报 → 通过；
4. 订阅链路：`library_id=NULL` 的订阅投递按规则落库、显式指定优先、
   挂库删除后回落规则 → 通过；
5. 监听导入：自动分派规则把华语片硬链进华语库主根、hardlink 跨盘在
   保存时被拦截 → 通过；
6. dispatch-preview：samples 正反两面、matched_count、conflicts 均正确 → 通过；
7. alembic 升级后存量库/监听规则行为与升级前一致（全量回归）→ 通过。
