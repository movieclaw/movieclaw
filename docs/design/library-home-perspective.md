# 媒体库首页透视：让首页由用户定义

> 状态：产品设计草案（2026-09-13），待评审。
> 样稿：[mockups/library-home-perspective-demo.html](mockups/library-home-perspective-demo.html)
> （排序与命名推荐是真跑的，抽屉里的改动会实时反映到背后的首页）。
> 上游：[library-home-up-next.md](library-home-up-next.md)（首页现有三行的口径）、
> [library-filtering.md](library-filtering.md)（合集是「存好的筛选」，4.3 已定「由用户选哪几个合集上首页」）。
> 先例：侧栏导航排序 `NavUiPrefs`（`settings/schemas.py`），本文的数据形状照抄它。

## 0. 一句话

首页 = 每个成员一份**有序的行清单**；每一行 = **来源 × 排序 × 名字**。

OmniFocus 的透视由三部分组成：规则（筛哪些任务）、呈现（怎么排、叫什么）、
位置（在侧栏第几个、要不要显示）。搬到首页上：

| 透视的部分 | 首页对应 | 现状 |
|---|---|---|
| 规则 | 一行滚的是哪一批作品：**一个库**或**一个合集** | 已有。想要「8 分以上的日漫」，先筛、存成合集、再上首页，**不新造第二套条件语言**（铁律 3） |
| 呈现 | 排序 + 名字 | 排序是现有 `WallSort` 加一档随机；名字由用户定，系统按排序给推荐 |
| 位置 | 顺序、显隐 | **本期要做的**。每个成员一份，能藏、能挪、能加、能恢复默认 |

## 1. 行的类型与能力

| 行 | 来源 | 排序 | 名字 | 隐藏 | 删除 |
|---|---|---|---|---|---|
| 接下来继续 | 内置 | 固定：最近播放（up-next 文档已论证不能引入入库时间） | 固定 | ✓ | — |
| 我的媒体库 | 内置 | 固定：管理页的库顺序 | 固定 | ✓ | — |
| 我的收藏 | 内置 | 未看优先（默认）/ 收藏时间 / 片名 / 评分 / 上映 | **固定**，它就是收藏，改名反而找不着 | ✓ | — |
| 库行（默认） | 一个库，每库自动一条，id `lib:<library_id>` | 入库 / 上映 / 最近观看 / 评分 / 片名 / 随机 | 可改，留空跟随推荐 | ✓ | — |
| 库行（自加） | 一个库，同库可多条，id `row:<uuid>` | 同上 | 同上 | ✓ | ✓ |
| 合集行 | 一个合集，id `row:<uuid>` | 合集自身 / 入库 / 上映 / 评分 / 随机 | 跟合集名走（一个东西一个名字，改名去合集页） | ✓ | ✓ |

「最近添加的 X 库」不再是一种特殊的行，只是库行的**默认排序**。用户把它改成
「上映时间」，它就变成「最近上映的电影」；再加一条同库、按评分的行，两行并存。

### 1.1 命名推荐

名字留空即跟随推荐，推荐由来源与排序实时生成；用户一旦手输，就不再跟着排序变。

| 排序 | 倒序（自然方向） | 正序 |
|---|---|---|
| 入库时间 | 最近添加的{库} | 最早入库的{库} |
| 上映时间 | 最近上映的{库} | 最早上映的{库} |
| 最近观看 | 最近观看的{库} | 不提供 |
| 评分 | 评分最高的{库} | 不提供 |
| 片名 | {库} A–Z | |
| 随机 | 随便看看 · {库} | |

方向开关只在正序有意义的排序下出现（入库、上映）。「评分最低」几乎没人要，
随机与最近观看谈不上方向。

### 1.2 「只显示我没看过的」

库行多一个开关。按评分排的行没有它，永远是同一批 20 部，那是一张海报不是一行内容。
后端已有 `w=unwatched`，只是一条参数。开着时推荐名不变，排序标签多一个「未看」。

### 1.3 随机

随机种子**按天固定**：页面轮询刷新不换一批，明天再换。否则用户会以为坏了。

## 2. 交互

### 2.1 静止态：还是一份看片的首页

行的骨架不变（横滚、海报、「查看全部」）。变的是每一行都是用户的。

- 排序标签（「按评分 · 未看」）和 `⋯` 都**收在悬停里**：静止态是看片的，不是配置的；
  但排序看海报看不出来，所以鼠标一到就得把当前值挂出来（与 filtering 5.1.1
  「看不出来的状态必须显值」同一条判断）。触屏 `⋯` 常驻，排序标签不显示。
- 空行照旧整段隐藏：偏好决定「想不想看」，数据决定「有没有」。
- 全部藏光时不出白页，给一个指回「自定义首页」的空态。

### 2.2 两处配置入口

| 入口 | 位置 | 管什么 | 频率 |
|---|---|---|---|
| 行菜单 `⋯` | 行标题右侧（悬停出现，触屏常驻） | **这一行**：改排序、只看未看、上移/下移、隐藏、编辑（库行）、打开合集（合集行）、删除（自加行） | 高，「想藏掉这一行」一次点击就在它出现的地方 |
| 「自定义首页」 | 页头，「管理媒体库」左侧；移动端为图标按钮 | **全局**：顺序、显隐、添加、恢复默认 | 低 |
| 「显示在首页」 | 合集页 | 把这个合集加成一行 / 从首页移除 | 与 Plex 的 Pin to Home 一致，写同一份偏好 |

### 2.3 抽屉：「自定义首页」

- 桌面右侧抽屉，移动端底部弹层。**首页留在背后并且实时跟着变**：关一行它从后面
  消失，挪一行后面顺序跟着换。没有「保存」，改首页是改货架不是提交表单。
- 列表每项：拖拽把手 · 类型图标 · 名字 · 小字「来源 · 排序」· 上移/下移 ·
  编辑（库行）· 眼睛开关。移动端拖拽换成上下箭头（拖拽在滚动容器里会抢手势）。
- **隐藏的行留在原位、压暗**，不挪到底部。再打开时回到原来的位置。
  隐藏的行在页面上没有实体，抽屉是它们唯一能被找回来的地方。
- 「＋ 添加一行」只问一个问题：**从哪来**。选一个库得到「最近添加的 X」，
  选一个合集得到它本身；排序和名字进「编辑」再改。已在首页的合集置灰标「已在首页」。
- 「恢复默认」是抽屉里唯一带确认的动作：回到出厂布局，自加行被移除。

### 2.4 编辑一行（库行）

来源（库）· 排序（分段控件）· 方向（仅入库/上映）· 只显示没看过的 · 名字
（占位文字实时显示推荐）· 预览条（这一行真实的前几张，与首页同一份数据）。
改动即时生效，「完成」只是关门。默认行换了库就变成自加行（id 从 `lib:` 变 `row:`），
该库的默认行下次合并时重新出现。

## 3. 数据

不新增表，不迁移。存在成员自己的 `member.ui_prefs`（超管走 `ui.preferences` 全局域，
与现有界面偏好同一条分流），`UiPreferencesSetting` 加一个 `home` 字段：

```jsonc
{ "home": { "rows": [
  { "id": "up-next" },
  { "id": "favorites", "sort": "unwatched_first" },
  { "id": "libraries" },
  { "id": "lib:1", "sort": "release_date" },             // 默认库行，改了排序、名字留空
  { "id": "row:8f2c", "library_id": 3, "sort": "rating",
    "unwatched": true, "name": "评分最高的动漫" },       // 自加
  { "id": "lib:2" },
  { "id": "row:a91e", "collection_id": 7, "sort": "random" },
  { "id": "lib:3", "hidden": true }
] } }
```

合并规则照抄 `NavUiPrefs`「存的是提示，不是契约」：

1. 存过的按存的顺序；没存过的内置行与每个可见库的默认行按出厂顺序追加在后。
   新库、新版本加的内置行，老用户一定看得到。
2. 认不出的 id 直接忽略：库被删、合集被删或被别人改成私有，那一行静默消失。
3. `sort`、`name`、`unwatched`、`asc` 全部可空，空即默认。
4. 上限 48 行，防脏数据，不是产品限制。

## 4. 接口

- 偏好读写：沿用 `GET/PUT /ui/preferences`，不加新路由。
- 库行数据：现有 `GET /ui/libraries/{id}/items?sort=&order=&w=unwatched&limit=20`；
  `WallSort` 加 `random`（按天种子，服务端 `ORDER BY` 用 seed 派生的哈希）。
- 合集行数据：现有 `GET /collections/{id}/items?sort=&limit=20`。
- 前端按清单逐行取数，**隐藏的行不发请求**。行数多到影响首屏时再考虑聚合接口，
  v1 不做。
- 首页布局只影响 movieclaw 网页。Jellyfin 客户端的首页是它们自己的，唯一共享的是合集本身。

## 5. 分期

1. 行清单模型 + 内置行/默认库行的显隐与顺序 + 行菜单 + 抽屉 + 恢复默认。
2. 库行可编辑：排序、方向、只看未看、命名与推荐；同库多行；随机排序。
3. 合集行：抽屉里添加、合集页「显示在首页」、排序覆盖。收藏行排序开关。

## 6. 刻意不做

- **多套具名首页**（「晚上追剧」「陪娃」切换）：多成员切换已经是一层视角，合集又是
  一层，单成员多套首页是同一件事的第三层。`rows` 套进 `views[]` 即可扩展，不现在做。
- 行的样式（卡片大小、横竖形态）：行的形态由来源决定，不是偏好。
- 在首页上直接编辑合集规则：去合集页，首页只覆盖排序。
- 跨库合并的「最近添加」：可作为后续的内置行 `recent:all`，不进 v1。
