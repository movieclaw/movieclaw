# 媒体库首页「接下来继续」设计

> 状态：已确认并实现（v2 把「最近观看」改成了「接下来继续」，见 1.0）
>
> 范围：只丰富 `/library` 首页顶部，不新增独立播放历史页。

## 1.0 v2：从「最近观看」改成「接下来继续」

初版这一行叫「最近观看」，卡片指向**最近播放的那个单元**，并按状态显示
「继续观看 10%」「已看完」「播放过」。跑了一段时间之后，问题很清楚：

**它是后视镜，不是指针。** 「已看完」的卡片摆在首页最贵的位置上，除了陈述
一件用户本来就知道的事什么也做不了；而看完一集之后，用户真正要干的事是看
下一集——卡片却写着「S01E03 已看完」，他得点进剧、找到季、滚到 E04。
**媒体服务器首页上最高频的那个动作，初版要三步。**

v2 把语义从"我看了什么"改成"我接着看什么"，整套规则收敛成一条：

    展示单元 = 从锚点起、按季集正序，第一个**没看完**且**文件在位**的单元；
    一个都没有就不出这张卡。

锚点仍是这部作品最近播放过的那个单元（排序也仍按它的 `last_played_at`）。
这一条规则不分电影/剧集就覆盖了全部情形：

| 状态 | 卡片 |
|---|---|
| 电影没看完（含 0%） | 它自己，继续看 |
| 电影看完了 | **消失** |
| 剧集当前集没看完 | 当前集，**不跳下一集** |
| 剧集当前集看完了 | 往后第一个没看完的，通常就是下一集 |
| 整部剧看完 | 消失 |
| 看完之后新入库一集 | **自己回来**——这正是「接下来」该有的语义 |

### 1.0.1 "看完"只认 `played`，不认"碰过"

初版判"看过"用的是 `played OR last_played_at 非空`。那条口径**放在 v2 会出错**：
先看了 E02 一半、又回头把 E01 补完，锚点变成 E01，而 E02 因为"碰过"被跳掉，
卡片指向 E03——用户看了一半的那一集反而回不去了。把没播完的单元算作"能接着看"，
正是这一行的本职。角标口径随之统一成同一条。

### 1.0.2 排序不引入入库时间

追到一半的剧、和刚补进新一集的剧，谁排前面？仍按锚点的 `last_played_at`。
不用入库时间的理由初版已经论证过，v2 同样成立：洗版成功会把旧版本的台账行
物理删除，该集的入库时间被刷新成洗版那一刻，早就看过的老集会被误报成"新内容"。

### 1.0.3 接口改名

`GET /playback/recent`（`playback.recent`）→ `GET /playback/up-next`
（`playback.up-next`）。数据的含义整个变了，留着旧名字是最坏的结果——
同一个名字、不同的东西。视图里同时去掉了恒为 false 的 `played` 与没人读的
`play_count`，新增 `advanced`（这张卡指向的是下一集，而不是上次那一个）——
它前端推不出来：`position_ms == 0` 同时意味着"下一集"和"这一集还没开过"，
两者该说的话不一样。

### 1.0.4 同时下线的：F5.2 推荐行

同一轮把「你常看X」「同系列里你还没看的」两行也撤了。它们"能解释"，但
**能解释不等于有用**：「你常看动画，这 12 部动画你还没看」本质上就是一个
类型筛选，用户自己点两下就有；包装成推荐，是拿解释性掩盖了单薄。
首页这块位置该留给"点了就能接着放"的东西。

### 1.0.5 隔壁那一行：「我的收藏」怎么排

首页顶部现在是两行，它们是一套：

| | 回答的问题 |
|---|---|
| 接下来继续 | 我**正在**看的 |
| 我的收藏 | 我**想**看的 |
| 最近添加 | 库里**新来**的 |

三行都是"点了就有事发生"，没有一行在陈述事实。

「收藏」在所有媒体产品里都是两件事被塞进一个心：**想看清单**（刷到点个心，
周末看——一个待办队列，看完就出队）和**珍藏架**（看过八遍，标记这是我的最爱
——一个陈列，时间序没意义）。两者要的排序正好相反。

本产品里它更接近前者，因为珍藏架已经有更好的归宿：手动合集（能排序、能改名、
能分享），而"刷到点个心"没有别的地方承载。所以：

- **首页那一行**把没看完的整体提前（`unwatched_first=true`），组内仍按收藏时间
  倒序。**一部都不删**——看过的心头好还在，只是靠后。收藏是用户显式说"记住它"
  的动作，悄悄藏起来比自动隐藏看完的电影冒犯得多。
- **`/library/favorites` 全量页**不传这个参数，保持纯收藏时间序。那里是"我收藏过
  什么"的完整账本，两处问的是不同的问题，给不同的答案才对。

判据用的是**收藏那一行自己的 `played`**：电影准确；剧集收藏整剧时哨兵行的
`played` 基本恒为假，于是剧一律靠前。这个近似偏向"早点露出"，而剧"没追完"本来
就是常态；要精确就得把本篇那套单元遍历搬过去，为一行的排序不值当。

### 1.0.6 「最近收藏」原来不是按收藏时间

排序原本是 `playback_state.updated_at` 倒序，号称"最近收藏在前"。但那一列是
**这一行任何写入**都会动的——进度上报、标记已看、记忆音轨选择——于是"两年前
收藏、昨晚看过一遍"的片会排到最前面。**看一遍不等于重新收藏一次。**

表上没有收藏时间，所以新增 `playback_state.favorited_at`（纯新增可空列，存量
回填成 `updated_at`——那是当前能拿到的最好近似，且不会比原来更差，因为原来
本就按它排）。只在 `is_favorite` 由非真变真时刷新：重复点心是幂等的不该改写，
取消收藏则留着旧时间不动（它已经不会被读到，下次真的再收藏自然刷新）。

写入点唯一：`movieclaw_playback.state.set_favorite`，网页详情页的心与 Jellyfin
客户端的心都走它。重新识别（reanchor）合并两行时取**较早**的那个——换身份锚点
不该让收藏看起来像刚发生。

用例先证伪后证真：排序改回 `updated_at`，两条回归立刻变红。

## 1. 目标与设计结论（v1 原文，口径已按 1.0 更新）

在媒体库页标题之后、现有媒体库卡片之前，增加一行可横向滑动的「接下来继续」。

- 一部作品一张卡；电影定位到电影，剧集定位到**该接着看的那一集**。
- 同一部剧只出一张卡，避免整行被同一部剧占满。
- 未看完显示续播进度；**看完的作品不出卡**（v2 改动，见 1.0）。
- 卡片点击进入现有媒体库条目详情；剧集携带季、集参数，让详情页直接展开并
  定位到对应集。
- 剧集还有排在**卡片这一集**之后、且没看完的分集时，剧照右上角显示「还有 N 集」；
  追平后角标消失。
- 横滑复用现有 `HScroller` 的触控滑动、触控板横扫和桌面悬停翻页按钮。
- 空时整段隐藏，媒体库首页恢复为当前布局，不放没有价值的空状态。

这是一块"接着看的入口"，不是完整历史：当前 `playback_state` 已足够支撑，
无需新增数据表或数据库迁移。

## 2. 页面信息层级

```text
媒体库页
├── 页面标题 / 说明 / 添加媒体库
├── 接下来继续                       ← 跨可见媒体库、按当前成员聚合
│   └── 横向海报卡：电影，或剧集该接着看的那一集
├── 我的媒体库                       ← 给现有库卡片补一个轻量分区标题
│   └── 现有媒体库卡片横排
└── 最近添加的「库名」               ← 现有内容，保持不变
    └── 现有横向海报行
```

「接下来继续」放在库卡片前，是因为它是回访用户最高频的内容入口；“我的媒体库”仍然保留在首屏内，管理能力没有被挪走。

### 桌面端尺寸

| 项目 | 规格 |
|---|---|
| 分区左右边距 | `24px`，与现有媒体行一致 |
| 卡片宽度 | 电影与剧集统一默认 `224px`（`xl` 为 `240px`） |
| 图片比例 | 电影背景剧照与分集剧照统一 `16:9` |
| 卡片间距 | `16px` |
| 分区标题到卡片 | `12px` |
| 进度条 | 海报底边内嵌，高 `3px`，圆角；不额外占海报下方高度 |
| 翻页按钮 | 复用 `HScroller`；悬停横滚区时出现，每次移动约可视宽度的 `85%` |

横卡原图统一经公共 `landscape-card` 派生预设输出：最大 `480×270`、WebP
质量 `78`、禁止放大小图。远程代理图与本地 metadata 资产共用
`ImageVariantService`、singleflight 和 `data/cache/images` 的 LRU 容量；同一
原图版本与预设只编码一次，详情页分集卡等后续消费面可直接复用该预设。

## 4. 单卡结构

### 4.1 剧集卡

```text
┌──────────────────┐
│ S01E03           │  ← 左上角常显，快速确认具体集
│       未看 2 集   │  ← 右上角按季集去重，只在数量大于 0 时出现
│                  │
│      海报         │
│                  │
│                  │
│██████████░░░░░░░│  ← 续播进度，示例 68%
└──────────────────┘
权力的游戏             ← 作品名，单行省略
次子                   ← 只显示分集标题；集号已在剧照内展示
2天前观看到 68%        ← 时间在前、结果在后，降低信息密度
```

剧集卡使用最近播放那一集的 `16:9` 剧照，与详情页分集横排一致；本地分集剧照优先，
其次使用 TMDB still，缺图时显示 `SxxExx` 占位，不裁切整剧海报冒充分集图。

“未看 N 集”统计的是**当前卡片所属媒体库里，季集排在卡片锚点之后、当前成员
从未看过、且至少有一份文件在位**的分集数。同一集的 1080p / 2160p 版本按季集
聚合后只算一集，已经全部缺失的分集不计入；电影不展示该徽标。

角标口径刻意不看入库时间，这是纠正上一版“入库时间晚于最近播放时间”的两个误报：

1. **看完不该再催**：整部剧看完之后，补齐旧季、重扫或任何一次入库都会让旧口径
   重新提醒一遍，而用户其实没有任何可看的新内容；
2. **入库时间本身不可靠**：洗版成功会把旧版本的台账行物理删除（见
   `docs/design/quality-upgrade.md` §7.1），该集的入库时间被刷新成洗版那一刻，
   早就看过的老集会被误报成“新入库”。

“最近添加”分区已经承担“库里来了什么新东西”的表达；最近观看这一行只回答
“我还能接着看什么”，两者不重复。判定“看过”只认播放事实——播放过或被显式
标记已看；只收藏、只记忆过轨选择而从未播放的分集仍算未看。

点击目标：

```text
/library/{library_id}/item/{media_item_id}?season=1&episode=3&from=recent
```

详情页读取 `season`、`episode` 后直接展开对应季，并将该集滚动到可见区域。参数失效或该集文件已经不存在时，安全回退到普通条目详情。

### 4.2 电影卡

```text
┌────────────────────────────┐
│       横向背景剧照           │
│██░░░░░░░░░░░░░░░░░░░░░░│
└────────────────────────────┘
触不可及
2011
4天前观看到 10%
```

电影图片优先本地 `backdrop/fanart`，其次 TMDB `backdrop_path`；两者都没有时，
用竖版海报放大模糊铺底，并在中央完整保留一张清晰海报，避免强行裁切主体。

点击目标保持现有媒体库条目详情：

```text
/library/{library_id}/item/{media_item_id}?from=recent
```

### 4.3 状态文案

| 数据状态 | 海报底部 | 卡片副行 |
|---|---|---|
| `position_ms > 0 && !played` | 按真实百分比填充 | `2小时前观看到 42%` |
| `played=true` | 进度条填满，并在末端显示小勾 | `昨天已看完` |
| `position_ms=0 && !played && play_count>0` | 不画进度填充 | `4天前播放过` |
| 时长缺失但有位置 | 不显示百分比，只画中性活动线 | `2小时前观看过` |

不把 `position_ms=0` 显示成“观看 0%”：底层会在不足 5%、拖回开头或仅收到播放开始时保留这一状态，界面无法准确区分。

## 6. 横滑与点击交互

- 鼠标：还能往某个方向滚时对应的翻页按钮**常驻显示**（静息 80% 透明度、悬停行时全亮），滚到边缘时对应按钮隐藏。首版是悬停才浮现，后改为常驻：滚动条已被隐藏，不悬停就没有任何「右边还有内容」的线索。触屏不渲染按钮，可滑线索仍是露出的半张卡。
- 触控板：支持自然横向滚动。
- 触摸屏：支持惯性横滑，滑动到边缘时不把剩余横向动量传给外层页面。
- 键盘：聚焦卡片后可按正常 Tab 顺序浏览；翻页按钮保留明确的 `aria-label`。
- 点击卡片：进入媒体库条目详情。剧集定位到具体季集，电影进入普通详情。
- 点击剧照中央的播放键：跳过详情页，直接进 `/play/<库>/<条目>`（剧集带 `season`/`episode`，全部带 `returnTo=/library`），从上次看到的位置续播。
- 横滑手势必须经过现有误触保护，不能在用户停住惯性滚动时误开详情——播放键与整卡各自过一遍判定，误触起播的代价比误进详情大（会真的建起转码会话）。
- 返回媒体库首页时，保留页面纵向位置；最近观看横向位置可作为实施时的低成本增强，不阻塞首版。

剧照中央的播放键在首版是**刻意不做**的：当时控制台没有自有网页播放器，播放三角会错误承诺「点了立即播放」。网页播放器上线后这个前提不再成立，播放键随即补上并常驻显示（触摸屏没有悬停态，藏在 hover 后面等于对一半用户不存在）；整卡进详情的语义不变，两个入口叠在同一张卡上。

播放键不在前端计算「从第几秒开始」：播放器起播前自己会问一次 `/playback/resume`，续播点与上次用的音轨都以那份服务端记录为准，与条目详情页的播放键同一条链路。

## 7. 数据口径

### 7.1 候选

从当前登录成员的 `playback_state` 读取，候选必须同时满足：

1. `last_played_at IS NOT NULL`；
2. 不是整季/整剧收藏哨兵行，即季号、集号均不为 `-1`；
3. 对应电影或剧集单元仍有在位文件；
4. 文件所在媒体库对当前成员可见；
5. 条目与海报信息仍能正常读取。

收藏但从未播放的条目不进入本区；收藏继续由详情页和播放器现有能力表达。

### 7.2 聚合与排序

- 先按 `media_item_id` 聚合，一部作品只保留 `last_played_at` 最新的叶子状态。
- 电影的叶子单元固定为 `(0, 0)`。
- 剧集以最新状态行的 `(season_number, episode_number)` 作为卡片锚点。
- 按锚点的 `last_played_at DESC` 排序，同秒时以 `media_item_id ASC` 保证稳定。
- 默认最多返回 20 部作品；这是首页展示上限，不代表历史保存上限。

这样既满足“剧集定位到集”，又不会因为连续观看同一部剧而让首页出现十几张相同海报。

### 7.3 多库与多版本

当前播放状态只记录媒体单元，没有记录播放时选中的 `library_file`，因此同一单元存在于多个库时无法还原“当时从哪个库播放”。首页按当前成员可见的库展示顺序，选择第一个仍包含该单元的库作为详情入口；它只影响跳转归属，不影响进度数据。

### 7.4 时间与进度

- 数据库存储 UTC，API 输出带 `Z` 的 ISO 8601；相对时间由前端按用户本地时区显示。
- `duration_ms` 复用现有播放领域的时长解析顺序：文件探测时长 → 单集元数据时长 → 作品元数据时长。
- `progress_percent = position_ms / duration_ms × 100`，显示时四舍五入为整数并限制在 `1..99`；已看完单独显示 `100%` 状态。
- 前端不重新实现 5%/90% 已看阈值，只消费后端已经归一化的 `position_ms` 与 `played`。

## 8. 建议业务接口

控制台应调用自有业务接口，不反向消费 Jellyfin 兼容 API：

```http
GET /api/playback/recent?limit=20
```

成功响应遵循项目统一信封：

```json
{
  "success": true,
  "code": "OK",
  "message": "",
  "data": {
    "items": [
      {
        "media_item_id": 14,
        "library_id": 2,
        "kind": "tv",
        "title": "权力的游戏",
        "year": 2011,
        "poster_url": "/images/assets/...",
        "backdrop_url": "/images/assets/...",
        "episode_still_url": "/images/assets/...",
        "season_number": 1,
        "episode_number": 3,
        "episode_title": "次子",
```

后端负责成员身份、媒体库可见范围、聚合、稳定排序和时长解析；前端只负责展示，不接受 `member_id` 或媒体库白名单参数，避免越权读取其他成员的播放状态。

## 9. 加载、空数据和错误

| 场景 | 行为 |
|---|---|
| 首次加载 | 暂不展示分区；拿到至少一条记录后再整体挂载 |
| 加载完成且无记录 | 隐藏整个「最近观看」，不显示空状态 |
| 刷新失败但有旧数据 | 保留旧数据，沿用页面现有 stale-while-error 行为 |
| 首次请求失败 | 隐藏本区并记录中文错误日志，不阻断媒体库首页 |
| 海报缺失 | 复用现有 `PosterImage` 占位图 |
| 对应文件刚被移除 | 后端过滤；若点击前失效，详情页按现有“不存在”处理 |

页面首次进入、恢复可见和现有 30 秒空闲轮询时刷新最近观看即可；不需要为该区增加高频轮询。

## 10. 组件边界建议

```text
LibraryView
├── RecentWatchRow                  新增：标题 + HScroller + 状态处理
│   └── RecentWatchCard             新增：播放进度与季集信息
│       └── PosterImage             复用
├── HScroller                       复用：横滑、边缘判断、桌面翻页
├── LibraryCard                     现有，不改内部结构
└── MediaRow                        现有「最近添加」，保持不变
```

不直接给通用 `PosterCard` 塞入播放状态：它当前承担发现页订阅动作、触摸悬浮层和媒体库操作，继续叠加续播状态会让一个组件同时承担两种点击语义。最近观看只复用底层 `PosterImage` 与 `HScroller`，组件更小也更容易测试。

## 11. 验收标准

1. 最近观看出现在页标题下方、媒体库卡片上方；没有记录时不占空间。
2. 只展示当前成员的数据，并过滤其不可见媒体库。
3. 一部作品最多一张卡；剧集显示并定位到最新播放的 `SxxExx`。
4. 卡片顺序严格按最近播放时间倒序，最多 20 张。
5. 续播、已看完、只有启动记录三种状态不会混淆，未知时长不显示虚假百分比。
6. 桌面鼠标、触控板和移动端触摸均可横滑；内容不足一屏时不出现翻页按钮。
7. 电影进入现有条目详情；剧集进入同一详情并自动展开、定位到对应集。
8. API 遵循 `success/code/message/data`，无新增数据库迁移。
9. 最近观看接口失败不影响媒体库列表和最近添加内容。
10. 最近观看横图响应为 WebP 且不超过 `480×270`，重复请求命中派生缓存。
11. 通过后端成员隔离/聚合/排序测试，以及前端卡片状态/横滑/剧集跳转测试。
12. 锚点之后存在未看分集时显示“未看 N 集”；多版本不重复、缺失集不计数、跳着看过的集不重复计数、整部剧看完后角标消失，且洗版刷新入库时间不会让数字跳变。

## 12. 首版明确不做

- 不新增完整播放历史页。
- 不增加播放设备、播放时长、暂停次数等分析指标。
- 不增加“清除最近观看”或手工排序。
- 不增加自动轮播、滚动吸附或无限循环。
- 不在控制台还没有网页播放器时增加播放按钮（网页播放器上线后已解除，见 §6）。
- 不修改现有 Jellyfin 协议接口和 `playback_state` 表结构。
