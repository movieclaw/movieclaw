## movieclaw v0.21.0

这一版围绕 **AI 助手更「会说人话」也更「看得见」**：会话页开始长出影音卡片，
微信 / Telegram / Discord 三家 IM 通道都能给助手发图片了。另有两条与网络相关的
修复——检查更新不再把限流误报成断网，通道类服务的连通性测试也补齐了。

> ✅ **本版无需更新 Docker 镜像**：运行时依赖没有变化（runtime 仍为 13），
> 在「设置 → 更新与维护」一键更新即可。

---

### 新功能

#### AI 助手会「画卡片」了

- 问助手「我的电影库有什么」「最近有什么想看的」，回答里不再只有文字：会话页会
  直接绘制**产品同款的影音卡片**——媒体库封面拼贴、带评分与「已入库 / 已订阅」
  斜标的海报卡（可悬停一键订阅）、带剧照和观看进度的播放卡、带追更范围与收录
  进度的订阅卡。
- 卡片数据由前端实时加载，看到的状态永远是当下的，不是助手回答那一刻的快照。
- 卡片组紧跟在对应的「处理过程」之后横向排列，助手再用文字讲结论。
- 仅网页端会话启用；IM 通道的回答仍是纯文本。

#### 微信 / Telegram / Discord 可以给助手发图片了

- 在这三个 IM 里直接甩一张图（海报、截图、报错弹窗），助手就能看——此前只会
  回一句「暂时只支持文字消息哦」。
- **先发图再打字会自动合并成一轮**（2.5 秒聚合窗口），不用把话挤在图的说明里；
  纯文字对话零延迟，不受影响。
- 一次最多看 4 张，单张上限 20MB；超大图服务端自动降采样，已在限额内的图原样
  保留（PNG 截图上的字不会被压糊）。
- **当前模型不支持看图时会明确告诉你**：回执里会写清是哪个模型、怎么换成视觉
  模型（或在供应商设置的「补录模型」里为它勾上「视觉」）。图片仍然会存下来，
  之后在网页端换个视觉模型重试同一条消息即可看图。
- 单张图下载或解密失败只跳过那一张，随图文字和其他图照常送达，并回执中文原因。
- 视频、PDF、语音等非图片附件暂未支持，这类消息若不带文字会收到明确提示。

### 修复

- **「检查更新」不再把限流和网络抖动误报为「无法连接 GitHub」**：此前在
  「设置 → 网络」把 GitHub 测成绿灯、点检查更新却偶发报错，两条路径口径不一致，
  日志里也看不出到底是超时、限流还是熔断。现在：
  - 错误文案分清了超时 / 连接失败 / **配额已用尽**（会说明走代理时该配额由出口
    节点所有用户共享，并给出恢复时间），末尾统一标明当前是直连还是经哪个代理；
  - 更新检查不再走熔断——每小时一次的后台任务攒下的失败，不该让你手动点的
    「检查更新」在冷却期内秒失败；
  - 网络级失败自动退避重试两次（限流则不重试，以免加速耗尽配额）；
  - 自定义 `UPDATE_API_BASE_URL` 带尾斜杠时不再拼出双斜杠（不少反代对此直接 404）。
- **补齐 Telegram / Discord / Webhook 的连通性测试**（感谢 @miniers）：这三项此前
  在「设置 → 网络」测不出结果；现在未配置账号或 Webhook、Token 无效都会返回明确
  的中文提示。
