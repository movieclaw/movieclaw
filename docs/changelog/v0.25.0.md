## movieclaw v0.25.0

这一版的主线是**把「慢」和「不知道从哪下手」当成 bug 来修**。媒体库多了
**重复文件治理**（后台扫描 + 结论落库 + 三档分诊，不用再对着满屏文件发呆）、
**蓝光原盘可播**、**每个成员自己的媒体库首页**；对账那条链路做了一轮系统性整治——
增量遍历、后台给前台让路、合集缓存，NAS 上「后台一跑前台就转圈十几秒」这件事到此为止。
播放器进度条修了八处真机复现的老问题（第二根手指、伪横屏拖不动、拖到片尾从头重播……），
订阅侧则补上了「取消订阅能不能顺手把文件也清了」。

> ✅ **本版无需更新 Docker 镜像**：运行时依赖没有变化（runtime 仍为 16），
> 在「设置 → 更新与维护」里一键更新即可。

### 新功能

#### 重复文件治理：后台扫描 + 结论落库 + 三档分诊

起因是两句真实反馈：「每次打开都特别慢」与「打开之后整屏都是文件，不知道从哪下手」。

- **不再打开就算**：检测过去跑在打开页面的请求线上——每次 GET 都现算全库重复关系，
  给每个候选文件各 stat 一次（网络盘上几千次往返）、各跑一遍发布名解析。现在它和
  「扫描媒体库」是同一种东西：按一次「开始扫描」，作业在后台跑一轮、结论落库，
  页面只读结论；媒体库扫描 / 整理结束后自动排一轮，通常打开就已经有新鲜结果。
  只有扫描在跑时才轮询，跑完即停。
- **结论会过期而不会误删**：读的时候按文件清单与台账现状逐单元比对，对不上的既不显示
  也不清理，等下一轮扫描修正——绝不按过期结论删文件。
- **三档分诊**：按「机器有没有把握」分成**可以放心清理**（一模一样）/ **建议清理**
  （档位阶梯真的分出了高下）/ **需要你决定**（其余）。最后一档再按取舍类型分组
  （分辨率不同 / HDR 与 SDR / 规格不全 / 同档不同版本），成组动作让你对
  「HDR 和 SDR 我两个都要」只回答一次，而不是在几百个单元上各点一次。
- **窄屏可用**：同一个单元从十二行压到四行——共有的规格与来源提到单元头说一次，
  文件名折掉公共前缀、差异的尾巴永远完整并独占整行（这一页的全部意义就是横向比对
  两个名字）。体积与码率钉在行尾不截断，点一下文件名给出原始文件名与完整路径。
- **「建议保留」修了一个会选错的老 bug**：未知档位此前被折成"最差"，于是一个没探到
  片源的文件必输给任何探到的——真实反馈里 HDR10 4.83 GB / 14.8 Mbps 输给了 1.22 GB。
  现在单侧未知的那一位直接失效、落到下一个信号，理由文案也改成真话。
- 「规格不全」这一组给出的是怎么补的指路（重新扫描媒体库补探分辨率、订阅页整季标注片源），
  一键清理时确认框会说清这一组的建议只按码率、来源、文件名挑，不是画质判断。

#### 蓝光原盘可播

单剪辑直出、多剪辑 concat 转封装，Jellyfin 客户端与自带播放器都能播。

#### 媒体库首页透视：每个成员自定义首页

首页从写死的清单变成每个成员一份有序的行清单，每一行 = 来源 × 排序 × 名字。

- 「设置首页」里可显隐、拖拽排序、换排序档位、只看没看过的、改名、添加库行 / 合集行、
  恢复默认；隐藏的行不发请求。没有设置过的用户看到的布局与改动前一致。
- 合集升为分区级视角并补上筛选，合集页 ⋯ 菜单可「显示在首页 / 从首页移除」。
- 海报墙新增 random 排序（按日期做种子，一天一个样），观看筛选新增「看过的」。

#### 取消订阅 / 减季可一并清理种子与媒体库资源

- 取消订阅时可选**一并清理**种子与媒体库文件；删除范围只覆盖这条订阅覆盖过的季
  （电影仍是整部作品），不再连带回收你自己刮削进来、从没订阅过的季。
- **减季**（订阅里取消勾选某一季）此前只把工单置为出域、什么都不删，现在保存成功后
  追问一次，按季执行清理：跨季包不删（删了会毁掉仍在追的季），清完把出域工单退回缺口。

#### 定时任务周期可配置 + 网络挂载感知

- 「设置 → 应用 → 定时任务」可以改每个任务的周期（每 N 小时 / 每天固定时刻 / cron）
  与启停，还能看到上次与下次执行时间；改完调度器立刻按新定义重排，不用重启。
- **网络挂载说实话**：根路径落在 NFS / SMB / FUSE 上的库，**无论开关**都不会建实时监听
  （收不到远端变更，建了只是白付递归 watch 的成本，还让人误以为有保障），编辑库对话框
  会直说「这里收不到变化、新文件由定期对账发现」。建库时根在网络挂载上，实时监控直接记为关。
- 有库在网络挂载上且对账周期长于一小时时，页面给出「调到每 1 小时」的一键建议——
  增量对账之后一轮只要几秒。只建议，不动你没点头的配置。

### 改进

#### 媒体库对账：后台一跑前台就转圈十几秒，到此为止

NAS 真机上一轮定期对账要 90 秒，期间每条碰数据库的请求被拖慢 10–40 倍（合集接口 13.5 秒），
用户正好打开媒体库就是「正在加载」十几秒。四块一起改：

- **目录 mtime 增量遍历**：没变的叶子目录（电影目录、季目录）直接跳过不列，成本从
  O(整库) 降到 O(变动)。只有定期对账走增量；主动扫描、根路径迁移永远全量，快照超过
  一周也强制全量一轮作保险。
- **后台给前台让路**：有 API 请求在途时，对账 / 扫描 / 补探 / 重复扫描在批次边界让路，
  前台清空立刻继续、最多等 2 秒。前台空闲时是一次整数比较，零开销。
- **合集列表不再押住首屏**：内容型合集（成员只取决于库里有什么）的成员数与封面落到行上
  缓存，跟着统计一起刷；279 个合集的库从 131 条查询降到两三条。「我的收藏」这类跟着
  看的人变的永远不缓存，分级受限的观看者照旧实时判定。
- 首帧只等合集列表 1.5 秒，超时先用上一份把页面画出来，真正的结果晚到再补一轮。

#### 媒体库浏览与响应速度

- **换排序只重拉墙**：过去换一次排序要重拉 8 趟请求（库列表、待办清单都跟着），墙得等
  最慢的那趟。现在只拉条目页 + 索引。索引条接口的排序与度量并成一趟查询，
  实测 130~470 ms → 30~50 ms；真实浏览器上「点排序 → 墙换内容」按评分 176 → 114 ms、
  按上映时间 301 → 185 ms。
- **删除影片改为两段式**：请求内只把文件 rename 进库内暂存目录（同一文件系统，毫秒级），
  真删放到响应发出之后做——几十 GB 的单文件在机械盘 / 网络挂载上不必再对着转圈干等，
  原盘 BDMV 目录尤其明显。语义仍是彻底删除、不可恢复；rename 失败退回原地同步删除。
- **收藏页与合集页支持排序**，合集页支持图床浏览；单库页图廊排序与海报墙对齐
  （全部档位、可切方向、「回到上次位置」两种形态共用一条记录）。

#### 界面

- 合集封面按实际张数铺满框，单片系列不再是窄条。
- 发现详情页的图片展示与背景策略并到媒体库条目页那一套；设置里的背景图改顶部对齐，
  与详情页沉浸背景同一口径。
- 对话框的思维链档位并进模型菜单——一个胶囊同时管模型与强度。

### 修复

#### 播放器进度条：八处真机复现的老问题

- **第二根手指碰到进度条会把正在进行的拖动当场作废**（横屏拿机时两只拇指都在那一带）：
  第二指的抬起被当成松手，提交一个你没确认的落点，之后真松手时一次跳转都不发。
- **鼠标拖动中按键盘或焦点被抢**同样会把拖动提交掉再清空，圆点停在半路。
- **伪横屏里进度条拖不动**：`touch-none` 被一条不分层的全局规则压掉，沿条拖动被浏览器
  当成翻页手势收走——iPhone 横屏看片正是这条路。
- **拖到片尾整部片从头重播**：对放完的元素调播放会先回到 0。
- **拖拽跟随叠 seek 导致松手后卡住十几秒**：拖动途中后一次跳转把前一次的索引请求打断，
  浏览器退回顺序扫描（跳 6 分钟要顺序读 47MB）。现在同一时刻最多只有一次跳转在途。
- **触屏快速甩到目标立刻松手，落点回到起点**：抬手读的是还没渲染出来的值。
- **松手后进度圆点被原生滑块补发的事件钉住**，从此不跟画面走，直到下次按下。
- **按住进度条不动超过四秒，控制条在手指底下淡出**；键盘连跳时同理。
- 直出档拖出缓冲时改为停住再跟随一次；直通档遇上「实测线路装不下源码率」不再逐级降档
  空忙，直接带实测带宽开转码会话。

#### 其他

- **删库 / 删文件会静默清掉观看进度**：孤儿清理判定「无引用」就删整行条目，而
  「看到哪了 / 已看 / 收藏」对它是级联删除——删库接口明确「不动磁盘文件」，连文件都不删
  却把全家的观看历史清了。现在条目还挂着用户数据时保留条目行，同一部作品重新入库时自动接回。
- **洗版下回来的新版本被入库端当低档重复丢掉**（issue #381）：规则组把 1080p 排在 2160p
  前（追剧省流）时，抓取端认定的升级到入库端被跳过，台账记「已导入 0 个」，任务永远停在
  「已完成」、旧版本永不替换。现在入库去重、抓取判定、洗版验证三处用同一条档位阶梯。
- **重复扫描把 API 占死一分钟**：全库扫描要跑几千次发布名解析，全在事件循环上同步跑，
  健康探针连续超时（再多几次就会重启整个容器）、后台任务心跳续不上导致整轮白算。
  现在批量扔进线程，最严重的一次卡顿从 9.74 秒降到 76ms。同批修了：任一文件回收失败
  就整个请求 500、扫描完全不响应取消、清理一个都没成功时结论行照样消失（文件还在、
  条目却没了，只能重扫整库找回来）。
- **一行蓝光原盘能让 Jellyfin 的「最近添加」整条 500**。
- **集号没解析出来的剧集不再被判成重复**；批量清理不再被超大单元卡死。
- 媒体库管理列表不再把「未声明收藏范围」当成待办提示。
