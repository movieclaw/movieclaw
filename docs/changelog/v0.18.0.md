## movieclaw v0.18.0

这一版的主线是**网页播放器完整落地**——打开浏览器就能直接看片，不必再依赖 Infuse、
VidHub 之类的外部播放器。核心原则是「尽可能不转码」：能直出的直出，实在不行才逐档降级，
最后才动 CPU。字幕走三条路径（SRT 原生轨 / ASS 特效渲染 / PGS 烧录），手机上有完整的
手势与全屏体验，iOS 走系统原生 HLS。

另外两件用户会立刻感知的事：**忘记管理员密码不再等于删库重来**（可离线重置，配置零损失），
以及**修好了 Infuse / Apple TV 上「转圈、搜不出东西」的两个真 bug**。

> ⚠️ **本版必须更新 Docker 镜像**（runtime 从 8 升到 9）。
>
> 播放器需要**硬件转码**能力，镜像里的 ffmpeg 已从 Debian 自带版换成 `jellyfin-ffmpeg7`：
> Debian 版的硬件加速覆盖不全（QSV / RKMPP / AMF 基本没有），更关键的是没有 GPU 色调映射
> 路径——用软件转 4K HDR 是幻灯片级性能。
>
> 只在「设置 → 应用」点一键更新是**不够的**，请先拉取新镜像重建容器（`movieclaw/movieclaw:v0.18.0`
> 或 `:latest`），再进行应用内更新。没更新镜像时，设置页会明确提示「需升级 Docker 镜像」。

---

### 新功能

#### 网页播放器

- **打开就能看**：媒体详情页与「最近观看」直接进播放页，无需外部播放器。支持剧集连播、
  续播点、下一集切换。
- **五档降级，尽量不转码**：直出 → Remux 直通 → 只转音频 → 硬件转码 → 软件兜底。
  浏览器能解的一律不碰，只有音频格式不认（比如 DTS）时才单转音频，画质零损失。
- **硬件加速**：支持 Intel（VAAPI / QSV）、NVIDIA（NVENC）、AMD（VAAPI）与 macOS
  VideoToolbox。「设置 → 播放 → 查看检测详情」会用真实的 1 秒转码逐个后端自检，不可用时
  给出**能照着做的中文提示**（缺哪个设备、要加什么参数），改完点「重新检测」即可。
- **字幕三路径**：
  - SRT / VTT 走浏览器原生字幕轨
  - ASS / SSA 交给 JASSUB 渲染，特效、字体、时间轴微调全保留（会自动抽取 MKV 里的内嵌字体）
  - PGS 图形字幕选中即烧录进画面（与 Emby 同款语义）
  - 选过的音轨与字幕轨（包括「关闭字幕」）会跨会话记住
- **默认字幕全端统一**：外挂 > AI 生成 > `default` 旗标 > 非 forced，网页端与 Jellyfin
  协议端（Infuse 等）用的是同一份裁决逻辑，不会出现「网页选中文、Infuse 选英文」。
- **移动端手势**：左半屏上下滑调亮度、右半屏上下滑调音量、双击全屏、进度条加宽命中区并
  常显把手；点画面只开关控制层，静止 4 秒自动收起，菜单打开或暂停时常显。
  iOS 上系统不允许调音量时会提示用侧键。
- **进度条缩略图预览**：拖动进度条能看到对应位置的画面。
- **iOS / Safari**：iOS 走系统原生 HLS，画中画与原生全屏都可用；PWA 里画中画被系统拒绝时
  给出「去 Safari 打开」的指引。
- **播放诊断面板**：当前走第几档、是否硬件加速、掉帧数、首帧耗时一屏可查（Emby 式分节）。
- **配置自动推导**：并发路数、输出高度、缓存配额按机器规格自动算，不需要你调；设置里只
  保留一个「允许软件转码」开关（真要用到时播放页会弹窗征求同意）。

#### 其他新功能

- **忘记管理员密码可离线重置，配置零损失**（issue #200）：以前超管密码忘了就彻底锁死、
  只能删库重来。现在在宿主机上跑一条命令即可重置：

  ```bash
  docker exec -it movieclaw python -m movieclaw_api.reset_password
  ```

  信任边界是「能访问 `data/` 目录 = 这台机器的主人」，与主密钥文件同一条线（Jellyfin /
  Vaultwarden / Gitea 都是这个思路）。整个过程**只覆写密码字段**，用户名、昵称、站点、
  下载器、媒体库、订阅等全部原样保留。忘了用户名可以用 `--show` 查（只读不写）。
  重置完不用重启服务，立刻就能用新密码登录。
- **站点刷流可暂停/恢复**：做种上行占满带宽会影响看视频，以前只能整个关掉刷流。现在站点
  `⋯` 菜单里一键暂停：在池种子批量压到 1 KiB/s 上传限速（**刻意不用下载器的「暂停任务」**，
  以规避 H&R 风险），任务与数据全部保留，恢复即回到正常节奏。暂停期间不会因为限速下的
  低速而误汰换种子。
- **规则集支持媒体来源白名单与偏好排序**：可以直接表达「只要 WEB-DL / 蓝光」或「WEB-DL
  优先于蓝光」，不必再绕着洗版目标去凑。五档来源：Remux > 蓝光 > WEB-DL > Rip > TV。
  分辨率仍是主轴，来源作为次级维度参与打分。
- **条目详情可删除外挂字幕与 AI 字幕**：每条外挂字幕（含 AI 生成的）挂一个删除键，确认框
  里会摆出**完整路径**（同一部片常有一堆同语言字幕，只有路径能确认删的是哪一条）。内封轨
  不给入口——删内封要重封装视频本体，与删一个文件不是一回事。仅管理员可见。
- **Agent 会话支持「在新会话中继续」**：以旧会话的当前上下文为快照创建一个全新会话，两边
  生命周期完全独立，删掉源会话也不影响新会话。适合旧会话因异常中断或历史损坏而无法继续
  请求的情况。会话菜单里还加了「复制会话 ID」。

### 改进

- **订阅详情重构为单视图「一集一条履历」**：以前「追踪明细」和「活动记录」分在两个标签页，
  想知道「这一集现在卡在哪、经历了什么」要靠肉眼对时间线；多季订阅一次平铺 70+ 行，页面
  能拉到三千多像素。现在：
  - 追踪明细按季折叠，默认展开最新一季与有在途工单的季，收起态带迷你进度条
  - 每集展开为固定形状的里程碑链：**定档 → 搜索 → 投递 → 下载 → 入库 →（洗版）**，
    第一个未完成的节点就是卡点，一眼可见
  - 集行是等宽状态胶囊，右侧对齐成一列，扫一眼就知道整季的推进形态
  - 原来的活动流水没有丢：搜索轮次收成顶部一行摘要（带下轮到期时刻），集级事件挂到链上
    对应节点，全量流水折叠在底部
  - 电影只有「正片」一条工单，不再需要点一下才展开，里程碑链直接常显
- **音轨与字幕改为语言芯片 + 分组列表**：以前逐条铺单字徽章，一个文件带十几条同语言字幕时
  摘要行只是把「有中文字幕」重复十遍，真正有区分度的格式、来源、文件名全埋在 Tooltip 里，
  手机上根本悬不出来。现在折叠态是语言芯片（`简体中文 ×4`；只有一条时直接给完整信息
  `泰语 · AC3`），点开是按语言分组的可滚动列表，行内给「格式 | 文件名或内封轨号 | 来源 |
  默认/强制」。音轨行右端常显最高规格徽章（如 `Dolby TrueHD 7.1`）。手机上走底部抽屉，
  行高 ≥44px，完全不依赖悬停。
- **侧栏「活动」入口可参与导航顺序排序**：「设置 → 外观 → 导航顺序」里现在能拖动活动的
  位置。已存过自定义顺序的用户位置不变，无需任何操作。（待处理与更新两个入口常态不渲染、
  有事才亮，仍不参与排序。）
- **刷流选种与汰换改为相对判据**：此前三个写死的绝对阈值互相掩盖，会让整池冻死在低产出
  状态（实测 68 个种一个都换不动，门外还有 19 个合格候选进不来）。现在汰换改为「候选比
  在池的更划算才换」的边际比较，并要求明显更划算才动在产资产；在下并发上限由带宽包络导出，
  对称大带宽用户不再被死死卡在 3 路；免费窗口够不够下完改按实测速率估算，不再用写死的
  5 MiB/s。H&R 保留期仍是唯一保留的绝对硬约束。
- 侧栏「活动」角标点进去落点跟着角标走：有需要处理的任务落到「需要处理」，只有进行中任务
  落到「进行中」，角标为空才回默认的观看视角；一级切换器的「任务」也补上同色同数的角标。
  侧栏、切换器、状态选项卡三处计数统一口径，不会再出现「侧栏 3 / 进行中 2」的自相矛盾。
- 活动页「最近观看」换成历史回拨图标，与「正在播放」的播放三角区分开。

### 修复

- **Infuse / Apple TV 上「一直转圈、媒体库空白」**：取流响应此前会剥掉 `Content-Length`
  改用 chunked，AVFoundation 系的播放器（Infuse / VidHub / Apple TV）拿不到长度就无法预估
  缓冲，退化成「开一个小 Range、读一点、掐断、再开一个」。真实日志里 40 秒内打了 89 个
  Range 请求、从磁盘读了约 2.2 GB——比整个 1.67 GB 的剧集文件还多，磁盘被打满后同一时刻的
  媒体库列表和封面全部超时。现在一律保留 `Content-Length`。
- **Infuse 上搜索完全不可用**：Infuse 的搜索页是两路并发，其中 `/Persons` 我们没实现，
  返回的是一整页 Next.js 的 404 HTML，Infuse 直接把整个结果页判为空——所以表现是「任何
  关键字都搜不出来」。现在补齐了 `/Persons`、`/Persons/{name}` 与 `/Search/Hints`，
  匹配口径也逐字对齐了 Jellyfin 本体（去变音符、标点转空格、折叠空白后做子串匹配）。
  **有意的行为变更**：不再用 TMDB 别名表匹配（搜 `The` 从 331 条收敛到 121 条），分集标题
  现在能搜到，剧名命中时不再把整季集数一并带出。搜索性能也从「全库水合再过滤」改成
  「先粗筛再水合」。
- **AI 字幕翻译用思考型模型必败 + 断点续传死锁**（issue #194）：三个问题叠在一起——
  ① 我们自己把输出上限写死在 8192，而思考内容与译文共用同一份额度，思考先写，JSON 必然
  半途被截断（被截断的响应照样全额计费却零产出）；② 失败块以「保留原文」写进断点后永远
  不会被重排，续传时开跑前的熔断预检拿历史失败数一比直接抛错，任务每次都在 20 秒内原地
  爆炸，**换模型也救不回来**；③ 序号畸形时抛的异常类型绕过了块重试，直接打死整个任务。
  现在：不再设输出上限（交给供应商按剩余上下文兜底），撞到供应商天花板就即刻拆块自适应
  （50→25→12，封顶两层）；断点里的失败块续传时重新排队翻译，熔断只统计本次运行真正失败
  的块。断点写盘也改成了原子替换，崩在写入窗口不会再让已付费的译文全部作废。
- **站点账号密码登录报错**：`RuntimeError: Attempted to send an sync request with an
  AsyncClient instance.` —— 表单提交改为显式编码后再发送，重复隐藏字段与 `+`、`&`、`=`
  等特殊字符都正确处理。
- **活动页「已传输」不再随换连接归零**：播放器每次 seek、每次续拉缓冲都会开新连接，旧连接
  的字节此前随计量器一起被丢弃，读数在整场播放里反复归零——观看进度都快跑完了，已传输
  却只有几百 MB。现在按整场累计（换集时上一集的收尾连接不会记到新一集头上）。
- **侧栏导航顺序刷新时闪跳**：自定义过导航顺序的用户，每次刷新都会看到侧栏先按默认顺序画
  一帧再重排。现在用首帧缓存消除，顺带把侧栏玻璃透明度、全站蒙版的首帧闪烁一起修掉。
  切换账号（登录、退出、401）时缓存会清掉，共享浏览器上不会闪出上一个账号的顺序。
