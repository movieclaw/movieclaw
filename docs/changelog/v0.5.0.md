## movieclaw v0.5.0

Jellyfin 兼容播放接口首发——VidHub 等播放器可直接连 movieclaw 看片，
外加订阅推送图文升级与消息推送页重构。

### ⚠️ 需要更新 Docker 镜像（runtime 2 → 3）

本版本的库封面拼贴与 Jellyfin 图片缩放引入了 `Pillow` 运行时依赖。
旧镜像用户在「设置 → 应用」会看到「需升级 Docker 镜像」提示，请先
`docker pull` 新镜像再更新应用。使用 docker compose 的用户建议同步
更新 compose 文件，补上 `7359/udp` 端口映射以启用播放器自动发现。

### 新增

- **Jellyfin 兼容播放接口**：VidHub、Infuse 等支持 Jellyfin 协议的
  播放器可直接把 movieclaw 当作 Jellyfin 服务器添加（地址即 movieclaw
  地址），浏览媒体库、海报墙、详情页并直连播放，无需另外部署 Jellyfin：
  - 覆盖登录、媒体库/条目浏览、剧集季/集导航、图片、取流（Range 断点
    续传，strm 直链 302）、播放进度上报与续播、标记已看/收藏、
    「继续观看」「下一集」「最新入库」等完整日常动线
  - 播放进度、已看状态、收藏在 movieclaw 侧持久化，多设备间互通；
    局域网内支持 Jellyfin 客户端自动发现（UDP 7359）
  - strm 直链仅接受 http/https/rtsp/rtp 协议，file 协议一律拒绝（安全
    条款）；兼容接口与业务 API/鉴权体系完全隔离
- **演职员信息全链路**：播放器详情页展示演员/导演（含头像），点开
  演员可查看其参演/执导的全部作品；头像经既有图片代理落盘缓存，
  离线时优雅降级
- **库封面「氛围光货架」拼贴**：以库内最近入库 4 部作品海报服务端
  渲染出氛围光货架构图，控制台首页与播放器库卡片共用同一张图——
  控制台库卡片渲染更快（一次请求替代客户端 9+ 张图合成），播放器侧
  库卡片观感与真实 Jellyfin 服务器对齐；入库内容变化时封面自动更新

### 改进

- **订阅推送升级为图文消息**：Telegram/Discord 推送带 16:9 横版剧照
  配图（无剧照回落海报），开始下载/已入库文案补齐年份与规格行
  （分辨率 · free · 做种数）；取图/发图失败自动降级纯文本，通知不丢
- **消息推送页重构**：按「接入通道 / 推送内容」分标签——已接入账号
  跨平台统一列表展示（运行状态 + 绑定人），推送事件开关与通道接入
  彻底分开；微信扫码改为点开绑定弹窗才出码，纯浏览不再触发副作用

### 修复

- **微信主动推送收不到**：订阅投递、入库完成等主动推送因缺少会话
  令牌而静默丢失，现持久化并复用绑定人最近一次的会话令牌（重启不丢；
  从未与 bot 聊过天的账号仍需先发一条消息建立会话，日志会明确提示）

### 说明

- 数据库迁移向前兼容（纯增表），应用内更新支持一键回退（跨版本回退
  由更新前的自动备份兜底）
