## movieclaw v0.24.0

这一版有一个大功能和一批「一直没收尾」的顽固 bug：媒体库有了**合集体系**（系列自动成集、
手动与跨库合集、合集分享），首页的「最近观看」换成了**「接下来继续」**；媒体库新增
**批量转移与根路径归并**（后端与 CLI），合并库、换盘、拍平目录不用再手工编排几百次；
**读路径做了一轮系统性优化**，家用 NAS 上打开剧集详情页的系统调用少了 97.9%。
修复集中在订阅与入库那条链路上——假种当正片下回来、任务卡在「已投递」/「已完成」永不收尾、
NFO 被自己写出去的副本盖掉，都是用户实际遇到并反馈过的。

> ✅ **本版无需更新 Docker 镜像**：运行时依赖没有变化（runtime 仍为 16），
> 在「设置 → 更新与维护」里一键更新即可。

---

### 新功能

#### 媒体库合集体系：系列自动成集、手动与跨库合集

- **自动成集**：TMDB 的 `belongs_to_collection` 与 NFO 的 `<set>` 落成系列信息，同系列作品
  自动聚成一个合集（只有一部时不下发，避免满屏「合集」都只装着一部片）。带**缺片补齐**
  （这个系列还差哪几部，一眼看到）、**合集隐藏**（墓碑可逆，随时能恢复）和存量库的回填作业。
- **手动合集**：自己拉片单，成员可增删、可排序，作品详情页有「加入合集」入口。
- **跨库合集与总览页**：合集可以跨媒体库，也有了统一的总览页；合集能分享出去，
  自动成集的规则条可以编辑。
- 作品详情页的「所属合集」用两行文字呈现，不再占一张海报卡的位置。

#### 成员级内容分级

- 内容分级限制（`ContentLimit`）现在只在一处产生、六个出口全部收窄——**包括此前漏掉的播放
  决策**：过去列表里看不到的内容，拿到直链仍可能播得出来，现在这条缝补上了。

#### 首页改成「接下来继续」

- 下线「我常看」「接着看」两行；「最近观看」改成**「接下来继续」**——从你看到的位置起，
  按季集正序找出第一个**没看完且文件还在**的单元，直接给出下一个该看的东西。
- 收藏行改为「没看完的排前面」。新增收藏时间字段，**收藏时间不再被任何一次播放写入顶掉**
  （此前收藏顺序会莫名其妙地乱掉）。

#### 媒体库批量重定位：批量转移 + 根路径归并（后端与 CLI）

合并库、换盘、把多级目录拍平这类事，以前要手工编排几百次单条转移，现在一次提交就行。

- **预检先告诉你代价**：要占多少新空间（同盘 rename 不算）、同盘还是跨盘（用真实 rename
  探针判，bind mount 那种「看着同盘其实跨盘」的情况骗不过去）、硬链接省不省、有没有重名冲突。
- **批量转移**：选择集是显式条目列表或整个库；搬运过程中逐成员现算路径。
- **根路径归并**：把库的多个根路径并成一个，先加后删、没搬干净绝不摘源根。
- **失败不会把库搬成一半就失联**：错误按「对下一个成员还会不会发生」分三级，连续失败会熔断
  成「已阻塞」，修好后可从检查点继续；跳过与失败分开计数。
- 可选的**同名合并**（`--on-conflict merge`，不是缺省）：同一部作品的文件并进去，撞名按既有
  多版本约定退让成「标题 (年份) - 分辨率.ext」。
- 顺带修两个老问题：磁盘写满（ENOSPC）被当成普通跳过、导致空转几小时；部分完成的作业让 CLI
  退出码为 0——Agent 会据此去删源库，**那是会真正丢数据的**。
- 本次仅后端与 `mclaw` CLI，Web 界面还没有。

#### 进度条预览生成开关

- 「设置 → 播放」新增「进度条预览」开关（默认开）。生成预览要通读整部影片抽帧，两小时的片
  约 30 分钟，低配 NAS 上感觉得到；用不上的人现在可以关掉。
- 关掉的是**生成**而不是删除：已经生成的预览照常可用，重新打开即恢复生成。

### 改进

#### 读路径优化：家用 NAS 上少掉大量随机小 IO

实测口径（440 条目 / 1600 文件实验台，按阶段归因的系统调用数）：

| 场景 | 改动前 | 改动后 |
|---|---|---|
| 剧集详情 | 32999 | **704**（-97.9%） |
| 电影详情 | 3386 | 506 |
| 图片回访 | 7380 | 1800（写归零） |
| 启动 | 33322 | 25393 |

大库（79 个库 / 3.7 万条目）每请求的 SQLite 页读：筛选栏 612233 → 9144，海报墙首页
69350 → 1531。主要做法：

- 外挂字幕与美术图的发现**按目录归组**，目录列举次数只与目录数有关而不是文件数，
  结果按目录指纹缓存——机械盘与网络挂载上感知最明显。
- NFO 改为**入库时吸收进数据库、读路径只读库**，不再每次打开详情页都去解析磁盘文件；
  只有你主动刷新元数据时才重读。
- SQLite 页缓存默认提到 32MB（可用 `MOVIECLAW_DB_CACHE_MB` 调整）；openai SDK 改为按需导入，
  启动时少读约 800 个文件。

#### 订阅召回：补上英文名，且候选词全部下发

- 此前主动搜索首选 TMDB 的「原始语言标题」，理由是「种子多为英文命名」——但那只在影片原语言
  就是英语时才等于英文名。一部韩语电影给出的是「악인전」，恰恰是中文 PT 站绝不会用的写法。
- 现在**英文名单独存一列**（存量条目靠元数据刷新自然回填），召回词集合（英文名 → 中文名 →
  原名）**全部下发**并按站点 + 种子 ID 去重，不再「第一个词有结果就不再搜了」——那个短路
  判据看的是「有没有结果」而不是「有没有用」。
- 每站每轮的搜索次数上限从 4 次提到 6 次（约每 50 秒 1 次）。

#### 其他

- **播放器拖动更跟手**：快速高频拖动时，手指停住后浏览器不再发事件，被节流吞掉的落点
  永远落不了地——20 种停住相位实测，改动前 17/20 追不上，改动后全部在 60 毫秒内追上。
  指针输入同时合帧，重渲染次数与指针频率脱钩（240Hz 下 204 → 51 次）。
- **侧栏「最近会话」不再反复重排**：多个会话同时生成时，列表排序键被流式产出每 80 毫秒
  刷一次，几个会话互相往最前顶。现在只在开跑 / 落终态时刷新。
- **进度条把手不再探出控制条左缘**：轨道两端各让出半个把手的宽度。

### 修复

- **分集的集名与简介被永久冻结**（无需任何自定义 NFO 即中）：我们把元数据镜像成 NFO 写到
  媒体目录，下一轮又把自己写出去的那份**无条件读回来**覆盖数据库，形成闭环——集名与单集简介
  就停在第一次镜像时的内容。**新播剧集最吃亏**：TMDB 初期只有占位的「第 N 集」，几天后补上的
  真标题永远显示不出来。现在会认出「这份是我自己写的副本」而跳过，用户自己写的 NFO 仍然优先。
- **用户的 NFO 可能被静默毁掉或静默失效**：在详情页手动选图会绕过吸收直接重写 `movie.nfo`，
  对还没回填过的条目意味着用户的文件被纯 TMDB 内容覆盖、且从此不再回填；另一条路是镜像写入
  被关掉（不想让 movieclaw 往媒体目录写东西的用户，正是最在乎自己 NFO 的那批）时，
  用户 NFO 在每次刷新后静默失效、文件却原封不动躺着。两条都已堵住。
- **订阅下回来 113MB 的「1080p」预告片当正片入库**：体积÷片长新增**极端档**，低于合理下限
  五分之一的直接否决（0.3 Mbps 跑 110 分钟只有 247MB，这样的正片不存在），否决点放在选优
  之前——放在投递前时它已经占掉了「唯一合格候选」的位置，拦下来等于这一轮什么都没投。
  贴近阈值的可疑档维持只记录不拦截。
- **删掉条目后重新订阅同一颗种子，任务永远卡在「已投递」**：入库台账按「路径 + 指纹」幂等
  且只进不退，删除条目不会动台账，于是同一颗种子再也入不了库、也不告警。现在台账结论过时
  （有更晚的在途投递）会重新入库。同时补上入库台账指向作品的外键——SQLite 会复用被删条目的
  id，此前台账可能指向一个毫不相干的条目。
- **洗版任务下载完成后卡在「已完成」永不收尾**：逐集发布的单集种子在下载器里目录名完全相同，
  一个监听条目同时匹配多颗种子，入库时整批文件被记到同一颗种子名下（E12 记成 E10 的种子），
  洗版验证于是对不上。现在来源戳**逐文件判定**（宁可不记，不可记错），并给洗版任务加了活性
  兜底——已经不可能再构成升级的任务会自动收尾。**已经卡住的历史任务在部署后下一轮巡检自愈。**
- **播放器取流速度读数虚高几百 MB/s**：四处算错（反推缓冲增长时取错了缓冲段、码率用峰值
  累计、304 重校验落在统计字段的缝里、最小采样时长还是老时代的数），拖一次进度条读数就飙到
  138~277 MB/s，真值只有 2.4 MB/s——正好把这行该回答的「是我线路慢还是服务端转不过来」
  答反了。
- **拖得很远之后，进度条与时间读数落在两条时间轴上**：跳出已转区间要换转码会话，而换会话的
  空档里进度条的参照点会静默掉回 0，于是文字读数显示落点（几十分钟）、进度条显示会话内秒数
  （几十秒）。现在「没有参照点」是一个显式取值，此时进度条退回与文字读数同源。

### 内部

- 新增播放器**拖动压测装置**（`scripts/player-soak-harness.mjs` 等），把真实模块按组件接线
  串起来跑带种子的猛拖手势，本轮就抓出三个组合问题（换会话那条路的跳转在质量数据里完全不存在、
  同一条路把卡顿时长灌到 84%、拖动跟随没夹片尾余量）。每条回归用例都带「改动前」开关，
  先断言旧接线确实会被抓出来。
- 新增 CI 守卫：走真实迁移链比对**模型声明的外键与数据库里实际存在的外键**——这类漂移此前
  测不到（测试库按模型建表，天然一致）。
- 本版数据库迁移全部为新增表、可空加列或补约束，满足「迁移只能向前兼容」的硬约束；
  应用内更新回退跨版本时靠更新前的自动备份恢复数据。
