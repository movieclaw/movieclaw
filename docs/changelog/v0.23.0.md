## movieclaw v0.23.0

距上一版两天，改动密度很高：**播放器**这一版被系统性重做了一遍手感（进度条每帧自绘、
移动端手势、章节刻度、外网跳转与黑屏），**媒体库与搜索页的长列表全部虚拟化**（几千上万条
不再卡），新增 **MCP 服务端点**让外部 AI 客户端能直接用 movieclaw 的服务目录，下载保存位置
有了**记忆与确认条**，以及一整套针对「同名同年下错片」的**身份置信度**治理。

> ⚠️ **本版必须更新 Docker 镜像**：运行时依赖有变化（runtime 13 → **16**），
> 只做应用内更新会在「设置 → 更新与维护」看到「需升级 Docker 镜像」的提示。
> 三处变更叠加导致：新增 MCP 官方 SDK 依赖（`mcp`）、mclaw CLI 的新命令编进镜像、
> entrypoint 与 Dockerfile 改为让 mclaw 随应用产物一起更新。
> **请先拉取新镜像重建容器，再做应用内更新。**

---

### 新功能

#### MCP 服务端点：把服务目录开放给外部 AI 客户端

- 此前只给站内 Agent 用的那套服务目录，现在可以开放成 MCP 端点：管理员可以建多个端点、
  各自勾选要暴露的服务，组合出不同的工具目录，给 Claude Desktop 这类外部客户端接入。
- 管理页按开发者控制台组织：列表 → 详情（概览 / 工具 / 设置）→ 新建，带**连通性自检**
  （真实协议握手 + 列工具 + 一次只读试调）和可搜索的工具目录。
- 令牌只存哈希、可轮换，签发与轮换需要管理员会话二次校验。
- 工具颗粒度两档可选：一命令一工具（展开）或一服务一工具（折叠）。

#### 播放器：章节刻度、移动端手势、横滑拖进度

- **进度条上画出章节刻度**，拖动气泡里显示章节名（只画内嵌章节；详情页那种按时长
  等距合成的场景图不当章节下发）。
- **移动端手势三件套**：画面上双击左右 ±10 秒、长按 500ms 进 2× 倍速（保音高，缓冲
  告急自动退出）、横屏锁屏。
- **横滑拖进度**：一屏宽 = 90 秒，滑动中画面正中给出落点与增量胶囊，抬手才真正跳一次。
- 暂停时可以用 `.` / `,` 逐帧步进；锁屏界面的进度条现在能拖了（补齐 `seekto` 等媒体会话动作）。

#### 下载保存位置记忆

- 搜索结果点「下载」后，保存位置按**搜索页标签栏的分类**（电影 / 剧集 / 纪录片 / 动漫 /
  音乐 / 游戏 / AV / 其他，八个桶）分别记住，不再是三个会漂移的桶。
- 命中记忆时弹**确认条**：分类、最终路径、下载器全部可见，确认一次再提交——不会再出现
  「点了下载，片子已经进下载器了才发现放错地方」。
- 记不记由你决定：完整弹窗底部的「记住本次选择」勾了才写；确认条上可以「更改」或「不再记住」。
- 记忆失效时给出中文原因（预检未收敛 / 种子没解析出身份 / 下载器已删除 / 目录已不在候选里），
  不再静默回落成弹窗。
- 记忆只对管理员生效——普通成员的下载本来就由服务端自动路由。

#### 媒体库记住「上次滑到哪」

- 海报墙、相册墙、图床浏览三种形态都会记住上次浏览到的位置（一库一条、最多 20 面墙、
  两周过期），重新进来时底部弹一枚胶囊问要不要跳回去；不点就往下滑，滑够一屏胶囊自动让位。
- **收藏页**同样补齐了两层位置记忆：从作品详情页返回时整个已加载窗口一起接回来，
  以及跨会话的「回到上次浏览的位置」胶囊。
- **iOS 主屏 App**：挂后台超过 30 分钟再回来也当重新进入（iOS 恢复 PWA 时不重新加载页面，
  此前那条路径永远等不到触发）；几分钟内的来回切换仍原样保持。

#### 媒体库三面墙新增「最近添加」排序

- 页头「⋯」菜单里多一档「最近添加」，给持续往库里添内容的人。常驻序（拼音序 / 内容时间
  倒序）不变——首次建库时全库入账时间挤在同一分钟，按入账排等于没排。
- 偏好记在浏览器里，三面墙共用；排序写进「回到上次位置」，换排序不会把你送到另一部作品那里。

#### 收藏页补上图床浏览

- 顶栏多了与单库页同一颗「海报墙 ⇄ 图床浏览」切换键。
- 收藏是跨库混排的一面墙，此前每格按自己主图选框比例、同一行高矮不一；现在整墙钉死 2:3
  竖框，横版封面居中完整显示 + 同图模糊铺底。

#### 身份识别：同名同年不再静默下错片

起因是订阅诺兰版《奥德赛》(2026)，系统下回来的是同名同年的另一部同名电影，静默入库并刮削了
错的元数据。这一版把「我这次有多确信」这条信息贯穿了整条链路：

- **投递前拉一次站点详情页读影片编号**（IMDb 等），编号对不上就不投——站点其实早就
  告诉了我们答案，此前一次都没读过。只对电影生效（同名同年撞车是电影独有的问题，
  而请求成本集中在剧集，对 PT 站保持克制）。
- **选种排序补上身份维度**：此前「只靠片名蒙的、做种数 999」会赢过「编号命中、做种数 1」。
- **分不出来时停下来问你**：同名同年的孪生作品会在待处理里点灯，可以「就是这部」或「不是」。
- **修正识别结果后订阅不再静默死亡**（bug 修复）：此前用户改正错配后，原订阅的工单仍停在
  已入库、订阅仍是已完成，它再也不会去找——用户要几个月后才发现。现在订阅会重新排队，
  错的种子写进负面记忆，不会「秒完成 → 再入库 → 再认错」。

#### mclaw CLI：活动页与媒体库分享进命令树

- 新增 14 条端点：`playback activity` / `activity end` / `history` / `stats watch` /
  `device revoke`、`dl tasks` / `torrent replace` / `torrent delete`，媒体库分享的
  创建 / 查询 / 撤销 / 列表，以及 `fs browse`。
- 新增精选命令 **`mclaw activity`**：把三份快照按网页同一口径合并成「要处理 / 进行中 /
  有人在看」。
- **mclaw 现在随应用产物一起更新**：改 CLI 不再需要重发 Docker 镜像（本次镜像变更也正是
  为了打通这条路）。

#### 其他

- **入库后自动补章节图**：新下载的片子不用等你点开详情页才有图。此前自动下载入库的新片
  只能靠详情页懒触发抓图，只用 Infuse / Jellyfin 客户端的用户则一直没有图。
- **PT 搜索图片模式统一到媒体库灯箱**：缩放、捏合、滑动翻页、点画面收起控件全部一致；
  触屏点海报直接开灯箱（此前要先弹抽屉再点「浏览图片」），灯箱顶栏塞进详情 / 投订阅 / 下载。
- **灯箱两侧补一对翻页键**，只在有鼠标的设备上出现（移动端本来就能左右滑）。图片库灯箱、
  影视库图廊灯箱、章节图灯箱三处一起生效。
- **播放器补上取流速度读数**，控制条顶栏、缓冲转圈下方、诊断面板三处可见——用来回答
  「到底是我线路慢还是服务端转不过来」。

### 改进

- **媒体库三面墙虚拟化**：海报墙 / 相册墙 / 图廊全部改为窗口化渲染，几千上万条时不再卡，
  开销与库大小脱钩。
- **PT 搜索图览模式大幅提速**：卡片改吃 328×492 的派生图而不是站点原图（实测单张
  93.5KB → 2.1KB），动图卡片只显示首帧（与媒体库海报墙口径一致），网格同样虚拟化。
  4× 降速的手机上 2000 条结果：挂载 5.5 秒 → 0.8 秒，滚动 42.8fps → 59.9fps，
  页面内存 44MB → 9.6MB。派生图框从 328 提到 720，修掉上一版做糊了的问题。
- **跳字母之后往上滑也能加载**：用右侧 A-Z 索引条跳到某个字母后，上方明明还有几千部作品
  却是一堵墙；墙顶补上反方向分页，补页时视觉位置纹丝不动。
- **播放器跟手**：进度条改为每帧自绘（此前位置只来自浏览器约 4Hz 的 `timeupdate`，圆点
  每 250 毫秒跳一格）；连按快进合并成一次跳转（转码会话里连按三次就是黑三下）；跳转不
  要钱时画面跟着手指走。
- **播放器更稳**：解码错误先就地自救再谈降档（这类错误播放器自己往往一秒内就能救回来，
  此前直接掉画质 + 几秒黑屏）；回退缓冲按字节预算而不是固定秒数（180 秒在 4K 原盘上是 1.8GB）；
  切后台回来会重新申请防息屏。
- **播放器外网四件事**：落在缓冲里的跳转不再掐掉在途的取流管线；换流与远跳用冻结帧盖住，
  不再闪黑屏；远跳时盖的是落点的缩略图而不是上一帧。
- **播放器控制条视觉重排**：按权重理成三档，取流速率移到顶栏、时间读数降级、横屏与全屏
  并成一张卡片移到进度条下方右侧；窄屏边距统一。按产品决定移除控制条上的切集按钮
  （片尾卡片与系统媒体控制两条路仍在）。
- **弹窗超长内容不再滚不动**：弹窗基座兜底滚动，十个最长的弹窗改成三段式，标题与操作
  按钮固定常驻。
- **NVIDIA 部署**：补上原生色调映射（`tonemap_cuda`，硬件自检真跑一遍确认后才启用），
  README 中英文补上缺失的 NVIDIA 部署说明。
- 章节图作业不再和扫描抢库租约——首轮回填可能跑几个小时，此前这几小时里点「扫描」只能干等、
  新落盘的文件迟迟不入账。入库触发的章节作业也降了优先级，不再挡住后面的入库。
- 待处理抽屉的顶栏为状态栏让位，iOS 独立 App 里 tab 不再被时间和电量压住。
- 灯箱顶栏的图标键在移动端放大到 44px。
- 缓存管理面板里「刮削图片资产」的说明补上章节图（一部片 8～12 张、约 1MB，本地抽帧产物）。

### 修复

- **转码后画面变色**（issue #331）：三处独立缺陷，共同根因是转码路径把色彩交给 ffmpeg
  隐式协商。现在确立一条不变量——任何转码输出恒为 BT.709 / limited / 8-bit 并显式打标签。
  最常见的一幕是浏览器不支持该编码（Chrome 遇 HEVC）先命中了判定链的前一档，HDR 判定
  就再也没机会执行，PQ 曲线被当 SDR 编进 8-bit，对比度只剩三成、红绿反转。杜比视界 P5 的截图不再泛绿，存量库的色彩规格
  也能补探上来。
- **硬件转码三处**（issue #344）：10-bit SDR 源不再编不出来（三家后端全中，硬件档直接失败）；
  BT.2020 的 SDR 源不再因为软件滤镜排在硬件帧前面而整条命令起不来；滤镜链落到软件侧时
  解码恒定留在硬件上，不再把 4K HEVC 10-bit 的解码压回 CPU。
- **播放进度七处 bug**：拖动被系统手势打断后进度点与时间永久卡住（进度条贴着屏幕最底边，
  正压在 iOS Home 指示条的上滑区里）；往回拖后已缓冲浅色底铺到一小时开外；右键 / 中键点
  进度条会当场跳转；换音轨 / 画质空档里的拖动被静默吞掉；点过进度条后快捷键全哑；
  跳转落点没有上界，越过片尾会开出一个转不出东西的会话；暂停时缓冲条不长。
- **取流速度读数虚高几百 MB/s**：改用浏览器网络栈记录的时刻而不是主线程处理到事件的时刻
  ——主线程一忙，几 MB 的分片就被算成传了十几毫秒，越卡读数越离谱，正好把这行该回答的
  问题答反。
- **iOS 主屏 App 里的画中画按钮点了没反应**：能力探测取错了 API，渲染出一颗死键。
- **iPhone 横屏时播放器控件命中区从 44px 掉到 36px**（尺寸原先挂在视口宽度上，横屏
  844/852/932 越过了断点），低于 HIG 最小值；改为按指针类型分档。
- **灯箱里点「下载」没反应**：命中保存位置记忆时弹的确认条被灯箱盖在身下——渲染出来了，
  只是看不见。
- **边下边入库会去复制下载器还在写的文件**，30 秒重试一轮直到耗尽失败。现在只搬白名单
  视频与其同名附属，其余文件留给整种完成后收尾。
- **洗版留下的旧任务永远等不到清理**，每轮巡检刷一条「找不到仍有效的替代源台账」。
- **「其他」库的条目转移修三处**：目标库有同名分组目录时被误判成阻断；整目录搬会把分组
  目录里别的条目一起卷走；身份锚不跟着改，导致源库里同一相对路径后来出现的另一段录像
  会被认成同一条目、一张卡片下躺着两段不相干的视频。
- 按用户决策撤掉条目页的「刮削归属」入口，库级刮削设置照常生效。
- 一次 Esc 只关最上面那层弹窗（此前顶层弹窗的 Esc 会往下穿透）。

### 内部

- 抽出 `MemberScopedMixin` + 成员级表注册表，删除成员时遍历清理——此前逐行手写，
  漏写一张表的后果不是残留垃圾数据，而是 SQLite 复用行 id 后新成员会继承前一个人的数据。
  守卫测试第一次运行就抓到一个既有漏洞（活动页的播放记录 / 观看统计从来没被清过）。
- 新增两份端到端验收脚本：`scripts/perf/e2e_player_feel.py`（真浏览器 + 真视频 + 真触摸
  事件，三档形态跑同一组断言）与 `scripts/perf/e2e_favorites_recall.py`（真实全栈 +
  320 部收藏的数据集）。
- 播放器的位置读数收敛成唯一一个纯函数，时间文字与进度条自绘只能调它——「胶囊报 9:58、
  进度条停在 19:00」这类两个读数各说各话的 bug 从此在结构上不可能。
- 本版五条数据库迁移全部是新增表或可空加列、无回填，满足「迁移只能向前兼容」的硬约束。
