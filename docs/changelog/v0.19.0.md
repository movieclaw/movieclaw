## movieclaw v0.19.0

这一版有四条主线：**远程硬件转码真正可用**（NAS 没显卡，就把转码交给一台 Mac）、
**设备授权**（命令行和 Worker 不再靠手抄令牌，出示配对码、人在网页点同意）、
**刮削与整理全面可配置**（语言、选图、命名模板、目录写入，还能按媒体库分别配），
以及**大库性能**——3823 个文件的整理任务此前十小时卡在 64%，现在 25 秒跑完。

> ⚠️ **本版必须更新 Docker 镜像**（runtime 从 9 升到 13），只在「设置 → 应用」点
> 一键更新是**不够的**。
>
> 三处运行时契约变了：① 容器内的 nginx 此前不转发 WebSocket 升级头，Mac Worker
> 的控制面会 404，远程转码根本连不上；② `mclaw` 命令行从 Python 换成 Go 二进制，
> 由镜像现场构建并内嵌 API 规格，旧镜像里没有这个二进制；③ Python 运行时依赖随之
> 变化。
>
> 请先拉取新镜像重建容器（`movieclaw/movieclaw:v0.19.0` 或 `:latest`），再进行
> 应用内更新。没更新镜像时，设置页会明确提示「需升级 Docker 镜像」。

> 📌 **仓库已迁到 movieclaw 组织**（`github.com/movieclaw/movieclaw`）。旧地址有
> GitHub 的 301 重定向，存量部署查更新不受影响，无需任何操作。

---

### 新功能

#### 远程硬件转码：把转码交给一台 Mac

NAS 和大多数容器环境没有可用的硬件转码能力，遇到 HEVC、4K 或浏览器不认的编码只能
用 CPU 硬扛。现在可以让另一台机器代劳：

- **macOS 菜单栏 Worker**（Apple Silicon，macOS 12+）：用 VideoToolbox 做 H.264
  硬件转码，构建产物随本版 Release 一起发布（`.zip` 附件），下载即用。
- **不需要把 NAS 挂载到 Mac 上**：Worker 通过带过期时间的签名地址读取源文件、把
  HLS 产物回传给 NAS，源文件与产物都不落 Mac 本地磁盘。
- **Worker 不可用时自动回落**：走已有的重试与降级链路，不会因为 Worker 掉线就播不了。
- Worker 自带 ffmpeg 的检测、下载与校验；播放诊断里能看到远程 Worker 状态与转码进度。
- 配置入口在「设置 → 播放 → 远程转码」（原「应用」标签下的旧地址会自动跳转）。
  播放时弹出软件转码征求同意的对话框里，也会引导管理员去开启远程转码。

#### 设备授权：不用再手抄令牌

Worker 的共享令牌、命令行的密码登录，过去各走各的，令牌既不知道是谁的、也没法单独
停用。现在统一成一套：**客户端出示一个配对码，人在已登录的网页上点同意**，令牌直接
回到发起它的进程，全程不显示在屏幕上——也就不会进剪贴板、shell 历史或者 AI 的上下文。

- 新增「设置 → 成员与设备 → 设备」分区（仅超管可见）：待批准的请求会摆出名称、类型、
  来源 IP 和配对码四项依据供你逐字核对，并用大白话写清这台设备**将获得什么**
  （Worker 只能转码，碰不到订阅和媒体库；命令行是全权，包括删除媒体文件）。
- 已授权设备一台一行，显示最近活跃时间，**一键吊销**。
- 权限继承批准者的当前权限，事后收权立即生效；**改密码不会连坐吊销设备**——密码管
  「谁能登录网页」，设备令牌管「哪台机器还该连着」，是两条独立的线。要停用一台机器，
  去设备页吊销它。
- **无人值守的机器另有一条路**：NAS 的定时任务、CI、无界面容器里没人能去浏览器点批准，
  设备页因此还提供「手工令牌」——创建后直接给你两行可粘贴的 `KEY=value`（服务器地址 +
  令牌），塞进 `.env` 或 `docker --env-file` 即可。地址取自「对外访问地址」，没配时会
  回落成当前浏览器地址并明确告诉你这是猜的。手工令牌是全权且不过期的，能打开浏览器的
  机器请直接用 `mclaw login`；它同样出现在设备列表里，可以一键吊销。

#### mclaw 命令行迁到 Go，一行安装

- 不再需要 Python 环境：命令行是独立的静态二进制，随 Release 发布 **六个平台**
  （Linux / macOS 的 amd64 与 arm64、Windows 的 amd64 与 arm64）。
- 一行安装：`curl -fsSL .../install-cli.sh | sh`（Windows 用 `install-cli.ps1`）。
- `mclaw login` 改走上面的设备配对，**不再接受密码**；`mclaw logout` 只清本地凭证，
  并会明确告诉你服务端令牌仍然有效、要去网页设备页吊销。
- 凭证按平台惯例存放（XDG / APPDATA），按服务器地址分别记录，权限过宽会拒绝加载并
  给出修复命令；`mclaw status` 直接告诉你凭证是从哪个文件读的。

#### 刮削与整理可以按你的口味配置

新增「设置 → 媒体库 → 刮削与整理」，把原先写死在代码里的规则开放出来，**默认值等同
于此前的行为，升级后不会有任何变化**：

- **元数据语言优先级**：不再是单选，而是一个有序列表（默认 `中文（简体）→ English`）。
  首位决定请求语言，标题/简介缺失时按序回落。
- **选图偏好**：海报与背景各自按语言优先级挑选，支持「跟随主语言 / 原始语言 / 无文字」
  三个特殊项；图片下载档位可调。
- **命名模板**：入库、整理、投递的目录名与文件名改为受控占位符模板，设置页里点击插入
  占位符、实时预览两组样例、随时恢复默认。
- **目录写入细分**：图片、NFO、分集剧照三项可分别开关。
- **按媒体库覆盖**：编辑媒体库时新增「刮削设置」页签，每一项都能选择「跟随全局」或
  自定义（动漫库配日语优先、电影库配中文优先，互不干扰）。全局页会标注「N 个库已覆盖」，
  免得你在全局改了半天不生效还找不到原因。
- **条目的刮削归属库**：一个条目按哪套配置刮，钉在条目自己身上（详情页 ⋯ 菜单里可以
  改，也可以交回自动判定）。存量条目会在下次刮削时自动推断并固化，无需任何迁移操作。
- 发现页底部新增院线地区切换（一行小字，选完即保存）。

#### 蓝光原盘自动入库

- 整个种子下载完成后，**完整保留 `BDMV` / `VIDEO_TS` 目录树**并一次性原子发布，只写
  一条台账；不 remux、不拼接、不动保种源。
- 解析 MPLS 主播放列表挑主片、用播放列表总时长覆盖单片段时长——不会再把几秒钟的
  `.m2ts` 分段当成一部电影。
- 硬链接零额外空间；跨盘复制按 64 MiB 分块续传，中途重启可以接着来，完成前对媒体库
  不可见。
- 多盘合集、剧集原盘、原盘与普通视频混装等拿不准的布局，一律保持待人工处理，绝不猜。

#### 其他新功能

- **失败任务可以「忽略」**（issue #221）：失败是终态，取消对它无效，此前失败任务没有
  任何办法从「需要处理」里下架，侧栏红角标永不熄灭。现在可以单条忽略，也可以在
  「需要处理」头部一次「全部忽略」，随时能在「已结束」里撤销。对字幕生成这类会自动
  重试的任务，忽略对话框默认勾上「不再自动生成」并**跨重启有效**（此前容器一重启，
  被忽略的任务下次扫描就原地复活）；手动触发始终不受限制。
- **订阅墙一眼看出哪些已经到手**：电影入库后打绿色「已入库」斜标，剧集收齐打「已收齐」，
  已到手的卡片压暗——亮着的就是还没到手的那些。此前电影订阅卡完全不显示收录状态。
- **媒体库「待处理」常驻入口**：缺失 / 待识别 / 身份复核 / 已忽略四张清单此前只能从
  头部胶囊进入，清单一空入口就消失（把待识别全忽略掉之后，恢复入口永久失联）。现在
  ⋯ 菜单里有常驻的「待处理 N」，计数为 0 也不隐藏。
- **任务中心的规格行补上 Remux 标记**：此前只显示「2160p · UHD Blu-ray」，与搜索结果
  页的口径不一致。
- **自建 gpt-oss 端点的格式残留会明确告警**：vLLM / Ollama 等未正确配置 Harmony 输出
  解析时，工具名会混进 `<|channel|>` 之类的标记，表现为「AI 助手时好时坏、满屏内心
  独白」。现在会直接告诉你这是推理后端的配置问题，并附排查建议。

### 改进

- **大库整理 / 转移不再被自己的进度拖垮**：现场是 3823 个文件的整理任务十小时卡在
  64%。根因是三层互相放大的固定成本（每写一次进度就把 2MB 的计划整行读一遍、每个
  文件都广播一次事件、任务列表接口原样返回这份大计划）。全链路仿真对比：1200 文件的
  整理 99 秒 → 6.2 秒，事故规模的 3823 文件 25.5 秒跑完，期间无关接口几乎不受影响。
  领域行为完全不变。
- **Infuse / Apple TV 首屏扫描提速约六成**：Infuse 每次启动会打一轮密集扫描，生产实测
  是 77 秒、365 个请求。改成「先用轻量查询建骨架、只为真正要渲染的条目装完整数据」后，
  完整扫描串行 7.2 秒 → 3.0 秒、并发 14.4 秒 → 4.9 秒。**330 个响应逐字节比对一致**，
  由新增的压测脚本长期守着。顺带修掉一处影响全站的数据库统计缺失问题。
- **豆瓣分季条目的订阅能正确收敛了**：豆瓣把剧集按季拆成独立条目（「中餐厅 第十季」
  是一条），而 TMDB 一剧一条。此前整段标题丢给 TMDB 必然搜不到，报「TMDB 未收录该
  条目」。现在改用季级证据（豆瓣首播日期 vs TMDB 的季播出日期）定案，并**同时解出
  TMDB 季号**回填到订阅弹层——实测豆瓣季号有 13% 与 TMDB 对不上（《奔跑吧 第十季》
  在 TMDB 是 S14），只认剧不认季会让你默认勾到差好几年的内容。73 条真实条目实测：
  命中 21 → 72，错配 2 → 0，普通标题零回归。
- **中文译名缺失时用同地区别名补位**：TMDB 的「译名」和「地区别名」是两套独立数据，
  大量华语用户常看的片子 `zh-CN` 译名槽是空的，于是以英文名入库、以英文名建目录。
  现在优先取同地区别名——一个 923 部电影的库里 8 部踩中，7 部拿回了大陆通行译名
  （蜘蛛侠：英雄无归、壮志凌云2：独行侠、不要抬头、黑寡妇……）。华语片不受影响：
  作品原声语言就是你的主语言时不走这条补位，中文原名不会被拼音（`Băo lián dēng`）、
  网友诨名或错别字投稿覆盖。
- **国综这类「季副标题并进片名」的资源不再漏配**：新增「别名 + 季名」的组合判定，并把
  NER 抽取出的片名段也纳入候选（仍由覆盖率、年份、类型三道守卫复核，不放宽既有判据）。
- **AI 助手遇到空响应先重试一次**：供应商抖动、限流降级、安全过滤误伤大多是瞬时的，
  原样重发一次通常就能拿到回复。连续两次才判失败，失败文案也从一堆开发者术语改成
  「我连续两次都没能生成回复，可能是临时故障，请稍后再发一遍试试」。技术细节全部下沉
  到日志。
- **设置页按功能重组**：从 5 组重排为 6 组，新增「概览」落地页（没配齐时给三步开局
  清单，配齐后是订阅链路体检 + 更新提示）；「成员」与「设备」合并为「成员与设备」；
  「智能」改为「通知与集成」；外部访问地址移进「网络」；「应用」瘦身改名「更新与维护」。
  命名一并大白话化（订阅→订阅规则、监听导入→自动入库）。各分区的标签页现在支持
  `?tab=` 深链，刷新、收藏、分享都不会丢失所在标签。侧栏顶部那块「设置 / 管理账号与
  工作台偏好」的标题也去掉了——它只是重复了页面上下文，白占一屏高度，去掉后
  1440×900 下不用滚动就能看到「媒体库」组。
- **清单拉不到不再伪装成「没有」**：四张待办清单的接口 500 / 超时 / 权限不足时，此前
  一律当成空清单静默吞掉，页面零提示。现在保留上一份快照并点亮重试提示条。
- **README 重写**：补上与传统六件套（Jellyfin + Sonarr + Radarr + …）的对比、五张真实
  截图（含移动端与液态玻璃效果）、按代码逐条核实的能力清单，以及经过两轮实测、堵掉两处
  静默失败的安装指南。

### 修复

- **自动入库在网络挂载上的静默黑洞**（issue #259）：源目录挂在 SMB / NFS 上、写入方是
  另一台机器时，文件事件常常永远不来，而兜底巡检把「监听注册成功」当成「这个目录有人
  管」直接跳过——下载完成的内容既收不到事件也不被扫，台账里连一行都没有，日志里一个字
  都没有，只有重启应用才能捞回来。现在被监听的目录最迟 6 小时保底重扫一次（事件路径正常
  时不会触发，行为与此前一致）。
- **写了 HDR 但没写具体格式的资源被规则组无条件拒掉**（issue #244）：种子名里常见的泛指
  `HDR` 此前既不在规则组的可选值域里、又会被白名单判为不匹配，于是这类 4K 资源被静默
  排除，用户还没有任何办法放行。现在泛指 HDR 统一按 HDR10 处理（白名单收 HDR10 即放行，
  只收 SDR 的规则组仍然拒绝，黑名单排除 HDR10 也一并排除它）。
- **主源从下载器里消失后，订阅卡在「已投递」再也动不了**（issue #238）：旧源已经不在
  下载器、新源又还没跑出进度时，工单一直停在「在途」，「立即搜索」和手动下载都以
  「没有缺口」拒绝，用户只剩「立即换种」可点——每点一次多攒一个同样下不动的源。现在
  下载器可达却连续三次（约 15 分钟）查无此任务，就把工单退回重找并写明原因，两个人工
  入口随之放行。洗版投递、还有试用源在跑、以及曾经下载完成过的任务都不走这条路。
- **入库时对照实测规格，货不对板不再完全静默**（issue #242）：投递前只能按种子名判断
  规格，入库时 ffprobe 的实测值其实已经在手上，却没有任何一处拿两者对照——「声称
  1080p、实测 960×540」就这么被吞掉，规则组的分辨率白名单形同虚设。现在分辨率与视频
  编码不一致会写一条明确的活动记录（x265/H.265/HEVC 算同一种编码，不算货不对板）；
  实测值还违反了规则组的硬过滤时，再给一条待处理告警让你复查。**只报告、不动文件**。
- **剧集订阅一季都没勾、又不追新时会静默变成「已完成」**（issue #256）：接口照样返回
  成功，订阅列表里出现一条绿色的「已完成」，实际一集都没搜过，重新点订阅也修不回来。
  现在这种订阅直接被拒绝并说明原因。只想追以后播出的新集（不勾季 + 打开自动续订）
  仍然照常可用。顺带修掉「补下缺失集」漏掉特别季（S0）的问题。
- **订阅详情里「下载」里程碑永远停在「进行中」**：文件落盘即整理入库，后端实际不写
  `downloaded_at`，于是任何一条已入库的订阅都显示成「下载 · 进行中」而紧邻的下一格是
  「入库 · 已整理入库」，自相矛盾到让人以为没入库。
- **首次开启软件转码时确认按钮「点了没反应」，以及关闭播放后后台还在跑 ffmpeg**：
  一次修掉四条来路（起播请求被超越后无人认领的转码会话、播放失败进错误态后心跳仍在
  续命、同意弹窗原样闪回、起播去重指纹漏了画质项）。
- **iPhone 上本可直出的片子被强制转码**，以及远程 Worker 掉线会作废已经缓存好的分片。
  同时优化了 Worker 的上传连接复用与断线重连。
- **扫描丢掉文件名里的 Remux 标记**：Emby / MoviePilot 风格的命名（`片名 (年份) -
  2160p Remux CHD.mkv`）此前落库后片源为空，洗版基线恒为「未知」不可比。实测一个
  918 部电影的库里有 240 部踩中。整理一次之后这个信息就永久消失了，所以这修的是存量。
- **附属文件判定收敛到一处**：整理 / 转移 / 回收此前各写了一份，已经分叉——同一个
  `foo-thumb.jpg`，整理时跟着走、转移时留在旧目录、回收时漏删；转移还漏了 `.strm`，
  会把独立的网盘占位文件当成附属一起搬走。顺带补上 Emby/Jellyfin 的 trickplay 预览索引
  （`.bif`）——实测一个 918 部电影的库整理后留下 567 个孤儿 bif，剧集库 3766 个。
- **改了命名模板后重新整理，旧目录不再留下只剩图片的空壳**：海报、NFO、分集剧照会跟着
  条目目录一起搬走。
- **原盘流分段误入库与任务膨胀**：现场是 209 个待处理入库作业，其中一部电影的原盘就占
  了 24 个——那些「电影」其实是几秒钟的 `.m2ts` 分段。同时修掉合集识别（`The Fast And

- **下载器失联时不再误放行**：qBittorrent / Transmission 暂时不可达、或多下载器只返回
  部分结果时，此前会退回「目录静默 + 探测」猜完成，对预分配文件和残缺片段会造成提前
  入库。现在改为等待恢复。
- **已忽略的入库条目留下的遗留作业会一起收口**：此前只取消最新一条作业，较早的
